# Hydro 评测比较器说明

题目评测设置中的比较器决定如何比较选手输出和标准输出。选择时要同时看 `checker_type`（比较器实现方式）和 `checker`（具体比较规则或程序）。对于常见的精度题，通常选 `checker_type: testlib`，再选合适的 Testlib 比较器。

## 比较器实现方式

| `checker_type` | 用途 |
| --- | --- |
| `default` | Hydro 内置文本比较。忽略行尾空格、制表符和 Windows 回车，并允许末尾空白差异；行内其他字符仍须一致。 |
| `strict` | Hydro 内置严格文本比较。只统一 Windows 回车，其他字符和空白都必须一致。 |
| `testlib` | 运行 Testlib checker。`checker` 填 Testlib 内置比较器名称，如 `dcmp`、`wcmp`；也可指定 checker 源码文件。 |
| `hustoj` | 运行 HUSTOJ 风格的自定义 checker，参数为输入、标准输出、选手输出。checker 以退出码表示通过或失败。 |
| `lemon` | 运行 Lemon 风格自定义 checker，可通过输出文件返回分数和说明。 |
| `syzoj` | 运行 SYZOJ 风格自定义 checker，由标准输出返回分数。 |
| `qduoj` | 运行 QDUOJ 风格 checker，参数为输入和选手输出，以退出状态表示通过或失败。 |
| `kattis` | 运行 Kattis 输出校验器格式的 checker。 |

内置 `default` 和 `strict` 比较的是文本，不会把数字解析成浮点数；例如标准答案 `2.5`、选手输出 `2.500000`，在这两种方式下仍属于不同文本。要容忍浮点误差，请用 `testlib` 的浮点比较器，或编写自定义 checker。

## Testlib 内置比较器

以下名称对应题目设置中 Testlib 比较器下拉框里的选项。误差是源码中设定的阈值；“绝对或相对”表示接近零时按绝对误差判断，否则也允许按相对比例误差判断。阈值越小，要求越严格。

### 数字与浮点数

| 比较器 | 规则 | 常见用途 |
| --- | --- | --- |
| `dcmp` | 比较一个浮点数，绝对或相对误差不超过 `1e-6`。 | 单个浮点答案，常见精度题首选。 |
| `acmp` | 比较一个浮点数，绝对误差不超过 `1.5e-6`。 | 需要固定绝对误差时。 |
| `rcmp` | 比较一个浮点数，绝对误差不超过 `1.5e-6`。 | 同 `acmp`，名字来自 Testlib 的预设 checker。 |
| `rcmp4` | 逐个比较一串浮点数，绝对或相对误差不超过 `1e-4`。 | 多个答案数值，精度要求较宽。 |
| `rcmp6` | 逐个比较一串浮点数，绝对或相对误差不超过 `1e-6`。 | 多个答案数值，常用精度。 |
| `rcmp9` | 逐个比较一串浮点数，绝对或相对误差不超过 `1e-9`。 | 多个答案数值，精度要求很高。 |
| `rncmp` | 逐个比较一串浮点数，绝对误差不超过 `1.5e-5`。 | 多个答案数值，按固定绝对误差比较。 |
| `icmp` | 比较一个机器范围内的整数，要求相等。 | 输出一个整数。 |
| `ncmp` | 比较一串有符号 64 位整数，要求逐个相等且顺序相同。 | 输出整数序列。 |
| `hcmp` | 比较一个任意长度的有符号整数，要求相等。 | 大整数答案。 |

`dcmp` 与 `rcmp4/6/9` 的区别不只是精度阈值：`dcmp` 读取一个数；`rcmp*` 读取并逐个检查答案中的数列。选择时需要保证输出数字个数符合题目要求。

### 文本、空白和顺序

| 比较器 | 规则 | 常见用途 |
| --- | --- | --- |
| `fcmp` | 按行比较字符串，行内容须完全相同。 | 文字输出或要求逐行精确匹配。它不是浮点比较器。 |
| `wcmp` | 按空白分隔的 token 比较，忽略空格、换行等分隔形式，但 token 必须完全相同且顺序一致。 | 一般 token 输出；数字仍按文本精确比较。 |
| `lcmp` | 逐行比较每行的 token 序列，行内空白差异可忽略，行数及 token 顺序须匹配。 | 要求保留行结构、但不关心行内空白。 |
| `yesno` | 比较一个 `YES` 或 `NO`，忽略大小写。 | 单个是非答案。 |
| `nyesno` | 比较多个 `YES`/`NO`，忽略大小写。 | 多个是非答案。 |
| `uncmp` | 比较一串有符号 64 位整数，不要求顺序一致。 | 输出顺序任意的整数集合；重复数字仍计入比较。 |

### 按测试点或分数使用的 checker

| 比较器 | 规则 |
| --- | --- |
| `caseicmp` | 比较格式为 `Case 1: <整数>`、`Case 2: <整数>` 的多组 64 位整数答案。 |
| `casencmp` | 比较格式为 `Case 1: <整数序列>` 等的多组 64 位整数序列。 |
| `casewcmp` | 比较格式为 `Case 1: <token 序列>` 等的多组 token 序列。 |
| `pointscmp` | 示例计分 checker，按选手答案与标准答案的绝对差值返回部分分。它不是一般意义上的浮点容差 checker。 |
| `pointsinfo` | 示例 checker，把选手答案和标准答案差值等信息作为 points info 返回。通常不用于普通答案比较。 |

`case*`、`pointscmp` 和 `pointsinfo` 的具体行为可能取决于 Testlib 版本及题目评测流程；普通题目的数值误差比较优先使用上面的 `dcmp` 或 `rcmp*`。

## 如何选择

1. 输出内容是普通文本且必须逐字一致：用 `default`（允许末尾空白差异）或 `strict`（空白也精确）。
2. 需要忽略空白格式，但 token 内容仍要精确：`testlib` + `wcmp`。
3. 输出一个浮点数：`testlib` + `dcmp`；如果题目明确规定绝对误差，可考虑 `acmp`/`rcmp`。
4. 输出多个浮点数：按题面误差要求选择 `rcmp4`、`rcmp6` 或 `rcmp9`。若题面只规定绝对误差，可考虑 `rncmp`。
5. 输出整数：根据一个整数、整数序列或无序整数序列选择 `icmp`、`ncmp` 或 `uncmp`。

误差应以题目描述为准，不要单纯选择最严格的 checker。若题面要求 `|选手答案 - 标准答案| ≤ 1e-9`，`rcmp9` 的阈值相符；若要求绝对误差，则选用相对误差 checker 前应确认标准库实现的误差规则满足题意。

## 示例：CF 492B Vanya and Lanterns

这题只输出一个实数，截图中的评测设置可选 `testlib`。如果按题面绝对误差 `1e-9` 严格判定，内置选项里没有完全对应的单值比较器：`dcmp` 使用 `1e-6`，`acmp`/`rcmp` 使用 `1.5e-6`。可以用自定义 checker 实现严格的绝对误差 `1e-9`；也可以按课程/评测环境的要求选择预设容差。

若接受接近 `1e-9` 量级的内置误差并且输出只有一个数，也可选 `rcmp9`。它逐个读取浮点数，使用绝对或相对误差 `1e-9`；在答案约为 `2.5` 时，相对误差条件对应的差值可达约 `2.5e-9`，所以它不等价于严格的绝对误差 `1e-9`。

例如标准答案为 `2.5`：使用 `dcmp` 时，`2.5000001` 与标准答案相差 `1e-7`，会通过；`2.50001` 相差 `1e-5`，会不通过。严格按绝对误差 `1e-9` 判定时，前一个输出也应不通过。不要选 `fcmp` 或 `wcmp`：它们按字符串/token 精确比较，`2.5000000000` 可能因文本不同而被判错。

另外，checker 只决定答案如何比较，不会修正程序计算错误。该题答案常按相邻路灯最大间距的一半以及两端距离的最大值计算；程序应使用浮点类型保存并输出结果。

## 实现依据

本文依据 Hydro 当前集成的 Testlib checker 源码，以及 Hydro 的 checker 调度实现整理。Testlib 内置 checker 的阈值属于固定值；需要不同误差规则或特殊判题逻辑时，应使用题目自定义 checker。
