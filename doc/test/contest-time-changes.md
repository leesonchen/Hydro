# 比赛与课堂测试时间修改验证

本次代码尚未发布，也未更新运行中的 Hydro 服务。手工验证应使用加载本地工作区代码的开发环境。

## 预期行为

- 沿用比赛、课程的现有编辑权限，允许修改未开始、进行中或已结束的测试时间。
- 比赛开始时间、总时长、个人限时发生变化时，保存前提示对成绩、罚时、提交有效性和积分结果的影响。
- 课堂测试修改开始或结束时间时，提示中额外说明课程达标状态可能变化。
- 取消提醒不提交；时间没有实际变化不提醒、不新增记录。克隆比赛或另存课程模板不修改原活动的时间记录。
- 比赛编辑页显示该比赛的“时间修改记录”。课程编辑页按课堂测试展示记录，默认折叠，新记录排在前面。
- 每条记录保存操作者 UID、操作时间、修改前后时间、个人限时、当时活动状态、报名人数及积分影响标记。系统自动调整使用 UID 0。
- 时间修改与记录在同一次数据库更新中保存，冲突或未成功写入不新增记录。
- 时间修改沿用现有赛制的成绩重算机制，保留历史提交；已启用积分的变更显示“可能影响积分，需复核”，不在本次操作中自动重写已结算积分。
- 课堂测试时间仍须处于课程范围内，开始时间须早于结束时间。原有题目、赛制和删除限制保留；把已开赛测试改到未来也不会解除这些保护。
- 配置变更在写入新时间前使旧课程快照失效；重算未完成时，相关成绩与达标结论待确认，不能解锁尚未开放的后续章节。此前合法授予的章节访问权及教师手工决定保留。
- 重算失败不回滚已保存的时间。编辑页显示“设置已保存，成绩重算失败”，由有编辑权限的管理者点击“重试成绩重算”；没有后台自动重试。
- 准备阶段失败会显示设置尚未保存；普通比赛重试其已保存配置，课程重试先同步当前课程中保存的测试设置。重试请求不提交整个编辑表单。

## 手工检查

| 操作 | 预期结果 |
| --- | --- |
| 有编辑权限的用户延长进行中比赛的结束时间 | 保存前提示，确认后保存，编辑页新增一条记录 |
| 有编辑权限的用户纠正误填的开始时间，包括改到未来 | 可以保存，记录保留修改前后的时间及原活动状态 |
| 修改时间后在提醒中选择取消 | 时间不保存，没有新记录 |
| 只修改标题，或把时间改回原值再保存 | 没有时间提醒，也没有新记录 |
| 调整比赛个人限时 | 保存前提示，记录显示修改前后个人限时 |
| 教师在课程编辑页延长已结束课堂测试的结束时间 | 允许保存；测试恢复进行中；课程编辑页显示记录 |
| 教师纠正已开赛课堂测试的开始时间 | 不再出现“不能修改时间”的错误；按赛制重算统计 |
| 连续修改同一活动两次，重新打开编辑页 | 两条记录均保留，最新记录排在前面 |
| 修改已启用积分的比赛或已认证的课堂测试时间 | 记录显示“可能影响积分，需复核”，保留认证证据供核查 |
| 无编辑权限的学生访问或提交编辑接口 | 仍然拒绝访问或修改 |
| 两个编辑请求发生冲突 | 拒绝过期写入，不额外追加一条未生效的时间记录 |
| 重算失败后，刷新编辑页 | 新时间和记录保留，显示明确失败提示及“重试成绩重算”按钮 |
| 没改时间，再次保存标题或其他普通内容 | 不自动重试失败的任务；手动重试入口仍保留 |
| 点击“重试成绩重算”或重复点击 | 使用最新提交日志恢复统计，不重复追加时间修改记录 |
| 更新过程中重启服务，再打开编辑页 | 未完成状态仍存在，可用同一按钮恢复 |
| 没有参赛的教师查看已恢复测试 | 不会因为缺少个人统计而一直显示“更新中” |

课堂测试的记录位于课程编辑页底部。比赛的记录位于比赛编辑页底部。记录中的时间按查看者的账号时区显示。

## 自动检查

```bash
node --test test/contest-edit-settings.spec.js test/course-template-state.spec.js
node test/contest-assessment-monitor.spec.js
node test/review-security.spec.js
node --test test/classroom-feedback-entry.js
```

后三个命令启动并关闭隔离的临时 MongoDB，需要允许监听本机临时端口，不连接现有 Hydro 数据库。HTTP 测试另使用隔离的临时配置；若本机已缓存测试数据库，可用 `MONGOMS_SYSTEM_BINARY` 指定缓存二进制以避免重复下载。

这些检查覆盖确认后提交、取消保存、无变化保存、克隆与另存模板、记录渲染、记录持久化、过期写入、课堂测试重新开放、ACM 时间重算、积分认证失效标记、手动失败恢复及两个模块的真实 HTTP 重试权限。

额外回归场景包括：旧结果读取不能在新时间保存后开放章节；旧评测统计写入不能覆盖新时间的统计；并发评测失败不能被另一项重算任务误判为恢复完成；提交日志与配置发生冲突时须重新计算，不能忽略条件写入失败。

本次功能的前端行为测试、39 项后台集成测试、30 项章节与权限测试、33 项隔离 HTTP 测试、后台 TypeScript 检查及修改文件的 ESLint 检查已通过。UI 构建和 UI TypeScript 检查也已通过；队伍、积分证据和提交来源回归也通过。

批量重算使用整场持久化保护，不生成逐人的临时重算标记。测试另验证了：重新加载进程中的模型后，管理者可接管未完成任务；旧任务即使随后恢复，也不能清除新任务的状态或使成绩退回旧版本。
