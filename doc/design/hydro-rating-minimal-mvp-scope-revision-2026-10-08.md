## 0. 一句话结论

**停止将“全站统一标尺、比赛 Rating 改造、综合排名迁移、多套评估模型、复杂资格认证”绑在首版开发里。首版只实现一个 1PL 通过概率模型，得到两个数：题目统计难度 `D` 和用户练习解题水平 `R`，先影子运行，再用未来作答验证其预测价值。**

面向用户的主要解释应足够简单：

\[
P(\text{完成})=\frac{1}{1+10^{(D-R)/400}}
\]

- `R = D`：模型预计完成概率为 50%；`R` 比 `D` 高约 400 分：约 91%；低约 400 分：约 9%。
- **这里的“完成”必须有固定含义：首次有效提交后，7 天内出现有效 AC。** 这是“本站正常练习条件下的完成概率”，**不是**首次提交 AC 率、独立考试通过率或 CF 官方 Rating。
- 分数用于选题和粗略的练习水平参考。不要用首版分数自动作出升班、淘汰、考级达标或比赛成绩结论。

## 1. 为什么改变方向

### 1.1 业务事实及讨论结论

机构的 Hydro 同时包含自由练习、课堂例题、作业、赛后补题及限时模拟。纸质教材提前发放，部分题目有参考思路或完整代码；AI 也可能参与练习。**这些提交是真实的学习活动记录，但未必证明独立完成。**

此前版本过度强调严格认证，容易导致大量学生没有评分；随后的 R0–R6 计划又把模型、跨域连接、公共 Rating、综合 RP、自动发布和完整验证绑在一个工程里。复杂度已经超过“先知道这题相对多难、这个学生当前适合做多难的题”的首要目标。

新的取舍是：**默认接纳正常记录，不做 AI 使用识别、不要求老师逐条确认；以基本去重和统一观察窗口形成样本，让真实未来数据告诉我们分数是否有用。**

### 1.2 保留、删除和延期

| 类别 | 内容 | 处理 |
|---|---|---|
| **必须保留** | 一位学生对同题重复提交合并；无尝试不算失败；排除测试与无效记录；时点明确；跨域题号不串用 | 首版必做。这些是统计正确性，而不是反作弊系统 |
| **必须保留** | 用户 `R`、题目 `D` 同一模型同一评分池；版本化、运行失败不覆盖有效结果；训练与未来验证分离 | 首版必做，尽量轻量实现 |
| **必须保留** | 现有 Hydro 判题、`difficulty`、旧 `rp/rpInfo/level/rank`、现行榜单行为保持不变 | 首版不迁移、不覆写 |
| **取消首版** | 逐条判断独立性、AI 检测、课堂帮助权重、复杂来源校正、教师逐项审核 | 不纳入首版；只有验证发现实际问题时再讨论 |
| **取消首版** | 完整开发比赛限定 A / 全量 B / 来源修正 C 三套并行评分产品 | **只新建简化模型 B**。旧榜、既有独立测评结果作为验证基线；A/C 留为研究候选 |
| **延期** | 跨所有域的公开统一标尺、跨年代精确成长标尺、锚点映射平台 | 先限定可比较范围，再依据效果决定 |
| **延期** | K1/K2 综合榜、比赛 Rating 重做、旧榜替换、段位与激励政策、全站正式公开 | 不作为首版验收范围；单独立项与批准 |
| **延期** | 详细时间点重测还原、复杂人工排除 UI、多层发布工作流 | 保留必要事实引用；不为历史不可恢复数据阻塞前瞻试验 |

> 不能为了让文档显得简单，删除底层必要的权限、隔离和基本可靠性；真正的简化是**缩小首版承诺**，不是把风险藏起来。

## 2. 首版产品边界

### 2.1 只新增两种统计结果

1. **题目统计难度 `D`**：在指定评分池、指定样本规则下，一道题相对于该群体的完成难度。
2. **用户练习解题水平 `R`**：同一规则下，从该用户近期有实际尝试的题目中估计出的水平。

原有人工/传统 `difficulty`（1–10）继续存在；**不要写入或复用该字段**。现有学习成就、比赛分、旧 RP 和排名全部维持原状。也不要创建第三套公开“课程能力分”“比赛能力分”“统一综合能力分”。

### 2.2 首版展示

- 优先：后台报告或小范围教师只读试用，显示 `R`、`D`、评估日期和最简状态：`暂定`／`样本不足`／`已估计`。
- 在经过未来期验证前，**不默认面向全体学生公开**。未来若公开，可在题目/用户页面增加单独模块，但不改变现有排名字段和排序。
- “尚未估计”显示空值，不以 0 或 1500 冒充真实能力；低数据量也不做精确到小数位的表述。
- 显示帮助文本保持一句话：**“根据本站正常练习记录估计；分数相等时，7 天内完成的模型概率约为 50%。允许参考资料的记录也包含在内，不等于独立考试能力。”**

## 3. 数据契约：尽可能短，但不得含糊

### 3.1 一次样本是什么

首版只用**提交触发型学习过程**，不以每条提交为独立样本。

- 每位用户、每道题（首期使用**域内题号及可确认的题目版本**），找到第一个合格的正式提交，记为 `t0`。
- 观察同一用户同一题在 `[t0, t0+7天)` 内的正式提交：**存在有效 AC 则 `y=1`；窗口结束、相关评测已确定且没有有效 AC 则 `y=0`**。
- 到批处理截止时窗口未结束，或关键的窗口内提交还在评测中：暂不形成成熟样本；不能把 pending 直接算失败。
- 首版每个**用户×域内题目版本**最多提供一次基础模型观测。同题多次 WA→AC、反复 AC、页面刷新、再次开启课程均不增加样本数。
- 未提交的题目不构造 `y=0`。比赛中“参赛但某题没提交”，可以是比赛模型的失败，不是本模型的失败。
- 可包含自由练习、课程、作业、赛后练习及比赛**中实际提交过的题目**；比赛没有提交的题不补负例。来源保留在样本元数据中，**首版不赋来源权重**。
- 排除 pretest/generate、作废/被取消的评测、测试服务账号及已确认不适用数据；正常 CE/WA/TLE 等属于未完成证据。具体以代码状态枚举核对，不能仅凭状态名称猜测。

**示例**：赛内 WA，三天后赛后补题 AC。新模型记为 7 天窗口内完成；**旧比赛结果与现有比赛 Rating 不受影响**。

### 3.2 不过度承诺历史与版本

- 不把不同域的相同 `pid` 当同题；首版**不自动归并跨域副本**。
- 有确切版本记录时按版本隔离；历史题目版本不可确认时明确标记 `unknown`，不要把当前文件哈希伪装成历史版本证据。对不明确样本做数量报告，必要时暂不参加标定。
- 使用提交发生时间判断是否落在 7 天内，使用当前有效评测结果决定当前样本标签。预测验证时，不能读取预测当时尚未知晓的后来判定或排除规则。
- 先从现在开始保存**真实的每日输入快照、评分结果和预测**。历史不可精确重建时，不必为追求“完整历史回放”无限扩大首版范围；近似历史只用于开发诊断，不宣称是严格前向验证。

### 3.3 使用时间范围

- 试验默认使用**最近 90 天内完成且已成熟的学习过程**，得到一套“近期练习水平与难度”快照；7 天与 90 天都是试验参数，不是教育结论。
- 首版固定这两个参数，不同时上线多组窗口和参数自动选择框架。
- **本期不承诺不同月份 R 的差值就是精确成长幅度**：90 天滚动窗口内学生和题目群体变化会带来标尺漂移。先判断同一快照内的预测是否有用；后续确需成长轨迹再引入稳定参考题。

## 4. 计算：只实现固定斜率 1PL

\[
p_{ui}=\sigma\!\left(\frac{\ln 10}{400}(R_u-D_i)\right),
\qquad \sigma(z)=\frac{1}{1+e^{-z}}.
\]

- 由同一批成熟样本**联合估计** `R_u` 和 `D_i`，以简单正态先验/正则化避免全成功、全失败和小样本数值发散。默认中心 1500 只是同一评分池内部的数值约定，**不能证明不同域或不同时间已可比较**。
- 可采用交替一维优化；数值实现必须收敛、可复现，输入不变重复运行不能重复加分。**不要把已消费过的历史再作为新的训练数据叠加到上一次后验。**
- 不强行给所有题和学生发布点值；全通过/全失败可以形成有信息但先验依赖强的估计，前端未必发布具体数值。无样本、缺少连接或数值失败返回明确的非正常状态。
- 在同一评分池里保证 `R` 与 `D` 使用同一标尺。首版按**单域或经过明确配置的单一可比较教学范围**分别拟合；可以盘点全站数据，但不宣称全站分数可以直接比较。
- 原 `rating-v2` 的比赛名次算法、600＋400 综合分**不作为此模型的更新公式**。可复用旧算法中的纯数值帮助函数，但不要混用分数含义。

## 5. 自动运行：保留最小可靠性

- 每日低优先级批量运行；**首版只更新影子结果/教师试用数据，不自动改动公开排名**。
- 每次记录 `runId`、`modelVersion`、`scope`、`asOf`、固定参数、输入快照标识与校验摘要。快照至少能确定本次实际训练的样本与标签，不能只保存一个无法还原的哈希。
- 新结果写入独立集合/命名空间，校验完整才把影子活动指针切到新 `runId`。失败保留上一有效版本，不先删活动结果。
- 页面/API 一次读取固定的同一 `runId`；不能把新用户分和旧题目难度拼成一组概率。
- 限制扫描字段与运行并发，不读取无关的代码正文、编译输出等大字段；不影响判题与教师反馈。
- 不依赖 AI-EDU，也不新增消息队列或专用大数据平台。

**建议最小数据对象**：`practice_rating_runs`、`practice_rating_episodes`、`practice_rating_users`、`practice_rating_problems` 和一份 `practice_rating_active` 指针。名称可按仓库既有规范调整，原则是尽量复用既有 MongoDB 与任务注册设施，不为未来 K1/K2 先建九个业务集合。

## 6. 验证：先回答一个问题

**首版最重要的问题是：提前预测为 70% 的未来有效作答，实际约有多少在相同口径的窗口内完成？**

### 6.1 最小验证步骤

1. 在某日 T **冻结**训练样本、`R`、`D`、模型与观察窗口；保存对未来作答的预测，不用未来结果改写 T 的预测。
2. 观察 T 以后实际发生的首次合格作答，等待各自 7 天窗口成熟、评测结果确定。
3. 按预先固定的区间分桶，展示预测完成率与实际完成率的比较、Brier 分数及样本数；和简单基线（如题目历史完成率、整体平均概率）对比。
4. 另用后续独立模拟赛做一次**外部参考检查**：日常练习 `R` 是否对独立表现有参考价值？这不是首版正式公开资格认证。
5. 对样本不足、没有足够未来观测或只有训练内拟合结果，统一报告**“尚无结论”**，不自动调整模型复杂度来追求好看的结果。

**不在首版同时实施**三套完整 A/B/C 评分引擎、大量分组统计认证、跨域等值研究或升班规则优化。发现明显持续偏差后再立新任务。

### 6.2 验收分两层

**工程验收（必须）：**样本语义正确、优化数值稳定、相同输入结果可重复、范围不串用、无训练未来泄漏、失败不污染活动结果、原有 RP/比赛/判题行为不变。

**效果评估（不预设已通过）：**未来期完成概率校准、简单基线对照、后续独立模拟参考、适用人群与不适用人群说明。若效果不足，维持影子运行，不公开，也不把“能算出数”称为成功。

## 7. 将原 R0–R6 调整为最小四步

| 新阶段 | 最小交付 | 不包括 |
|---|---|---|
| **M0：口径与夹具** | 固定当前源码基线；明确数据规则；少量脱敏样本与旧榜回归检查 | 大规模重做旧 Rating V2 |
| **M1：作答过程抽取** | 从现有记录生成 7 天二元样本；去重、成熟度、时间与来源处理；基础测试 | 教师逐条认证、反作弊、复杂人工排除 UI |
| **M2：联合模型与每日影子运行** | 1PL `R/D`、简单状态、独立快照、失败不覆盖；内部只读查询 | 全站统一标尺、K1/K2、旧榜替换 |
| **M3：未来期验证与教师小范围试用** | 冻结预测、未来完成率/Brier/基线报告；教师解释与问题清单 | 自动公开、段位、招生/升班决策 |

完成 M3 后再单独作 **是否继续公开、是否需要稳定锚点、是否需要来源差异项、是否实施排名改革** 的业务决策。原 R0–R6 的历史文档保留供追溯，但**不得继续把其全部阶段作为本轮“完成定义”**。

### 建议 PR 拆分

- **PR-A（M0/M1）**：数据规则、提取器、夹具、样本正确性测试。
- **PR-B（M2）**：纯算法、运行脚本、最小快照/指针及失败恢复。
- **PR-C（M3）**：冻结预测、未来期验证工具、教师只读试验视图、运行报告。

每个 PR 有独立验收；不合并、不部署、不修改生产字段，除非另行明确授权。

## 8. 首版关键验收用例（建议至少覆盖）

| 编号 | 场景 | 期望 |
|---|---|---|
| T01 | 同一学生19次 WA 后在第7天内 AC | 一条 `y=1` 观测 |

| T13 | 数据库写入一半失败 | 活动指针仍指向上一完整 run |
| T14 | 学生 R 与题目 D 来自不同 run | 查询层拒绝混合计算概率 |

## 9. 对现有 Codex 计划的明确修改映射

| 原方案内容 | 本轮调整意见 |
|---|---|
| Q01「R0–R6 全部分期开发」 | **收缩为 M0–M3**；R4–R6 的正式榜单迁移取消首版排期，后续另行审批 |
| Q02「全站所有域纳入计算」 | **允许全站盘点，但首版按域/明确可比池独立建模**；不得用相同先验宣称全站同分数 |
