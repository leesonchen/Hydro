## 1. 架构决策

旧方案“AI-EDU 反馈服务与页面＋Hydro 预填入口／薄代理”会使反馈写入依赖 AI-EDU。本方案替代该设计：

> Hydro 独立负责线下反馈的认证、授权、录入、保存、查询、撤销和复测待办。AI-EDU 是可选的数据使用方，不是保存链路中的必需服务。

这里的“本地”是指 Hydro 自己的服务及数据库，不是浏览器缓存，也不是承诺断网可用。不配置 AI-EDU、AI-EDU 停机、学生没有 AI-EDU 账号，均不得影响本地反馈。Hydro 自身或现有 MongoDB 不可用时，不能确认保存。

线上课程的 IDE、细粒度代码轨迹、提示和 AI 分析仍在 AI-EDU。本轮只修改 hydromod，不要求同时升级 AI-EDU。

| 数据 | 权威来源 | 其他系统的角色 |
|---|---|---|
| 线下教师观察、撤销、复测处理 | Hydro | AI-EDU 可选读取和分析 |
| 线下班级／课程的材料可得条件 | Hydro | 可被引用，不代表学生实际使用 |
| 提交代码和最终评测结果 | Hydro 原有记录 | 反馈只关联 rid，不修改结果 |
| 线上编码轨迹及 AI 辅导 | AI-EDU | 本轮不开发 |
| AI 生成的解释和建议 | AI-EDU 派生数据 | 不覆盖 Hydro 原始观察 |

## 3. 第一版产品范围

### 三个快捷动作
| 显示名称 | 类型 | 可选细项 |
|---|---|---|
| 指导过 | GUIDED | 思路、调试 |
| 核对过 | CHECKED | 关键思路、边界、代码解释 |
| 需复测 | NEEDS_RETEST | 题意理解、边界、迁移 |

说明文字可空，最多 500 个 Unicode 码点；不要求掌握度评分、置信度或长评语。“核对过”只表示进行了核对，不自动表示掌握；“指导过”与“核对过”可以并存。

记录主体是学生 × 题目 × 活动，提交编号可选。无提交学生也能记录。没有记录不等于独立完成，不生成全班待填清单，不设置教师录入配额。

### 页面闭环
先在 Hydro 课程管理页内提供快捷记录、最近记录、待复测，再增加记录页的预填入口。默认选择目标后一次点选可保存；细项和备注可展开。不得先跳转 AI-EDU 再返回。

活动、学生、题目可可靠推导时预填；同题属于多个课时且不能唯一定位时，要求选择上下文，不能猜测。

待复测可标记“已处理”，记录处理人、时间、可选备注／rid。处理不自动等于学生复测通过，不生成能力认证。

### 纠错和材料条件
追加 `OBSERVATION_RECORDED`、`OBSERVATION_RETRACTED`、`RETEST_RESOLVED` 事件，后两者关联原事件，不直接覆盖原始观察。本批只实现第一类事件，撤销和处理在 H1 实现。

隐私删除是独立的授权清理流程；不能以审计为由拒绝合理的数据清理。

线下材料可得条件由 Hydro 配置，班级／课程继承，题目按需覆盖，设置一次后不要求每堂课重复确认。只表示“纸质讲义或参考代码可以获得”，不能自动变成“某学生参考完成”。该项在核心录入闭环之后，不阻塞首轮上线。

## 4. 本地保存协议

教师浏览器 → Hydro 同源 Handler → Hydro 本地授权与校验 → Hydro MongoDB → 保存回执。

保存链路不依赖 AI-EDU API、AI-EDU 登录、远程身份映射、AI 分析或新增 Redis/Kafka。

建议新增独立集合 `classroom.feedback.events`；不污染 `record`、`contest`、课程成绩和公共积分，不将追加记录塞入单个课程或学生的无限增长数组。

| 字段 | 约束 |
|---|---|
| `_id` | 根据域、操作者和 requestId 派生的稳定事件键 |
| `source/schemaVersion/eventType` | 服务端生成：hydro / 1 / OBSERVATION_RECORDED |
| `domainId/operatorUid` | Hydro 当前服务端会话，不接受客户端自报 |
| `studentUid/pid` | 正整数，实际关系由本地授权适配器核验 |
| `activityType/activityId` | course 或 homework；规范化活动 ObjectId |
| `nodeId` | 可选课程节点，必须属于当前课程 |
| `rid` | 可选，存在时核验域、学生、题目和活动 |
| `kind/detail/note` | 白名单动作，可空细项／备注 |
| `recordedAt` | 服务端记录时间，不自动代表实际指导发生时间 |
| `requestId/requestHash` | 一次操作的稳定请求键、规范化内容摘要 |

输入结构验证不等于对象关系授权。Handler 应以当前域、路由活动和登录身份为准，拒绝冲突参数。

### 幂等和确认
一次点击生成一个 requestId，超时重试沿用；新的教学观察使用新键。同键同内容返回原记录，同键不同内容返回冲突，不覆盖。

以数据库确认的单次插入作为保存边界。稳定 `_id` 的唯一约束用于跨进程重试与并发；不依赖进程内锁。每次请求，包括重试，都重新授权。已失去权限的用户不能借旧请求键读取记录。

未确认写入、超时、数据库错误不能假报成功。回执丢失时界面显示“保存状态待确认”，保留当前表单和请求键供重试。

本期不启动同步队列，不采用“保存事实，再单独非原子写队列”作为可靠同步保证；缓存、日志和分析失败不能要求用户重新创建已确认的事实。

### 查询和索引
按域、活动、学生、题目分页查询。待复测由事件关联派生，可建立可重建的本地投影；投影失败不丢原始事实。先满足一个班级的查询，不预建复杂事件平台。

建议在真实适配阶段按 Hydro 现有机制建立：
- domainId + activityType + activityId + recordedAt + _id
- domainId + studentUid + pid + recordedAt + _id
- 加入撤销／处理后按关联事件查询的索引

不要创建“学生 × 题目 × 动作”唯一约束，否则不同时间的真实观察会被错误合并。幂等由请求键承担。索引须验证查询计划。

## 5. 权限与后端开发

复用现有会话、域权限和课程班级关系，但不能仅凭宽泛权限位放行。尤其 `EDIT_HOMEWORK_SELF` 不能被解释为可以编辑任何课程。

H1 必须校验：
1. 功能开关启用；当前为有效管理／授课身份，学生及学生代入模式不得写入。
2. 当前域和活动存在；操作者是有效授课教师、维护者或有明确管理权限者。
3. 目标学生属于可管理活动名单，包含经过核验的临时调课学生。
4. pid 属于活动；nodeId 与题目关系正确。
5. rid 可空，非空时不得关联别人或其他活动的提交。
6. 创建、查询、撤销、处理分别授权；教师备注不自动对全域学生公开。
7. 撤销通常限原教师或明确授权的管理者；关联事件必须在同一域和活动范围内。
8. 使用 Hydro 现有防 CSRF、输出转义、认证过期处理和限流，不增加跨域免鉴权端点。

建议新增：
- `model/classroomFeedback.ts`：真实集合、索引、查询和追加事件适配。
- `handler/classroom-feedback.ts` 或课程模块中的 Handler：同源 API／页面。
- 课程管理及记录页模板中的轻量入口：修改前查清实际模板路径。

建议 API（尚未实现）：
- GET /course/:tid/feedback
- POST /course/:tid/feedback
- POST /course/:tid/feedback/:eventId/retract
- POST /course/:tid/feedback/:eventId/resolve

作业使用同一服务与独立权限适配，不复制实现。课程节点变化、学生调班后，历史记录的查询和管理权限需明确测试。

## 6. 故障行为

| 故障 | 预期行为 |
|---|---|
| AI-EDU 停机、超时、DNS 失败 | 本地录入、查询、撤销、复测待办正常；保存链路无 AI-EDU 请求 |
| 不配置 AI-EDU／无 AI-EDU 学生账号 | 正常；不要求补远程账号或密钥 |
| Hydro 已保存但回执丢失 | 同键重试返回原记录，不重复 |
| Hydro 数据库不可用 | 不确认保存，明确错误，保留当前表单 |
| 浏览器断网 | 不确认保存，不把内存草稿当作已保存 |
| 重试前权限被撤销 | 拒绝，不绕过授权 |
| 派生分析／投影失败 | 原始事实保留，可重建 |
| 关闭功能开关 | 不删除数据，不影响正常做题和判题 |

本期默认不做浏览器持久化离线队列。后续需要断网录入时，单独处理共享电脑、退出登录、账号切换、加密与数据清理，不能把学生备注长期无条件放入 localStorage。

## 7. AI-EDU 后续可选消费

建议由 AI-EDU 拉取或使用受控只读适配器消费，而不是在教师保存时由 Hydro 请求 AI-EDU。本期只保留稳定事件键和来源。

后续独立 AI-EDU PR 再实现：
- 以 (hydroInstanceId, eventId) 幂等导入；实例 ID 在配置和备份恢复后稳定，避免不同部署同号用户混淆。
- 在消费端映射用户；未知账号待映射，不阻塞 Hydro。
- 历史回补、撤销和处理事件、错误重试、数据清理传播。
- 显示同步截止点，不能将“没有同步到帮助记录”解释成“没有获得帮助”。
- 时间游标只是增量优化，不将客户端时间或插入前时间当成绝对提交顺序；须重叠扫描、周期对账，或另做可靠 delivery/outbox。
- 若选 outbox，事实与待投递状态原子持久化；投递失败不影响本地回执。
- AI 解释属于派生数据，不覆盖原始观察，不直接改变 RP／Rating／比赛难度。

这不是本次录入功能的上线前提。
