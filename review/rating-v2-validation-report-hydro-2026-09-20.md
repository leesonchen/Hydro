## 〇、重要环境声明：hydro ≠ hydro2

历史报告（2026-09-19 算法验证、影子、抽查报告）全部产自 **hydro2** 容器（230 场 rated 比赛、607 题观测、8,666 条校准观测）。本次验证的 **hydro 容器是另一份数据**：

| 指标 | hydro2（历史报告） | hydro（本次） |
|---|---|---|
| rated 比赛（试验口径） | 230 场载入 / 222 处理 | **2 场载入 / 2 场处理** |
| 域 | cpptrain 等 | exam、aiedu、prepare 等（**无 cpptrain**） |
| `ratingv2_shadow` | 5,966 条（shadow-trial） | 验证前为空 |

因此历史报告中的生产数字（slope=0.8868、provisional=172、分桶 MAD 0.0127 等）**在本容器不可复现，也不应复现**——它们是 hydro2 数据的产物。本次验证的目标是：**在 hydro 容器上证明算法机制本身正确、稳健、隔离、可操作**（即"同一台机器换个数据库也能一次跑对"），算法层面的统计结论仍以 hydro2 报告 + 仓库合成数据测试为准。

## 四、发现与建议

1. **（环境差异，非缺陷）** hydro 容器 rated 数据量（2 场）不足以在默认口径下产出难度与校准——如需在本容器持续演练完整链路，要么沿用 `difficultyMinPriorEvents:1` 的诊断口径，要么将后续插班测试标记为 rated 积累数据。
2. **（文档勘误建议）** 操作指导 §3 称参数"全部可配置并带默认值"，但 `rating-v2-audit` 的默认值由 Schema 注册层注入——绕过 hydrooj CLI 直呼 `run()` 时必须显式传全 `rules` 等参数（否则 `$in needs an array`）。随版本发布走 CLI 不受影响，建议在指导中补一句备注。
3. **（既有结论的重申）** 本轮再次实证"影子集合是唯一写入目标"与"难度零回流能力"两条纪律；正式切榜前按指导 §6.3 完成 duration 对照与公示的前提在 hydro2 侧依然成立。
4. 低门槛诊断跑的校准 slope=1.1431 与 hydro2 的 0.8868 方向相反：前者 n=55 的噪声、后者 n=4,371 的稳定估计，不构成矛盾；也再次说明 **slope 必须每次回放重估**（已自动化），不可跨环境搬运。

## 五、第一轮结论（2 场 rated 时期）

1. **机制正确性**：单元测试 27/27（含合成真值恢复）+ 容器内独立复算（单调性、期望-实际对账、公式逐分重算、成就重算）全部通过，未发现任何计算缺陷。
2. **工程稳健性**：换库换容器后一次跑通，0 失败 0 发散；文档数量与理论值精确相符；异常输入（非有限分数、全错题、SE 超限）均被既有闸门拦截。
3. **安全隔离**：源集合只读经三轮前后计数验证；rating 状态跨口径运行逐字段不变，证明难度优化不回流能力模型。
4. **判定：rating-v2 新算法在 hydro 容器环境验证合理，具备继续推进 P1/P5 的条件**；算法统计结论（校准参数、难度值域等）仍以 hydro2 生产影子数据为准。

### 7.4 校准斜率分析（本环境 slope=1.3864）

引擎拟合 slope=1.3864（对半切分 n=322/321），与 hydro2 的 0.8868 方向相反。独立复核：

- **方向是真实信号**：slope=1 分桶显示系统性"欠自信"（低尾期望 6.9% vs 实际 0%；高尾 94.3% vs 100%）——本环境学员能力方差真实大于评分初期展开的方差（多数人仅 1~2 场、Tanh 软饱和限幅），预测被压平，需要 k>1 收紧。10 次随机对半切分独立重拟合斜率为 **1.108~1.523（均值 ≈1.28）**，方向稳定、幅度有噪声。
- **收益评估**：分桶 MAD 0.0394 → **0.0241（降 39%）**，与 hydro2 报告的降 36% 同向；全量 Brier 0.1497 → 0.1485，朴素基线 0.2496（**模型优于基线 40%**）。引擎留出集 Brier 0.1594→0.1613 的轻微变差落在 10 次随机切分的噪声带内（7/10 次改善、3/10 次变差，|Δ|≤0.004）——n≈640 下斜率点估计不稳，属已知小样本限制。
- **M15 残差诊断**：0 题超 25pp 残差。

### 7.5 第二轮发现与建议

1. **难度与能力分在本环境判定合理**：单调性 -0.989、拟合对账 ≤2.1pp、能力-解出相关 0.782、头部三榜一致、闸门全部按设计收口。
2. **（口径建议）** 本容器若作为难度演练环境长期使用，`difficultyMinPriorEvents=1` 是当前数据规模下的合理工作点；正式生产（hydro2 类环境）维持默认 5。两口径可并存（不同 poolId），互不污染。
3. **（已知限制）** slope 点估计在 n≈640 时不稳定（1.1~1.5 波动），展示层引用时应视为"方向修正"而非精确值；hydro2 报告 §17 已将校准观测项登记，此处同样适用。
4. 16 道 0 解出题正确保持 degenerate 不发布；若后续场次有人解出，重放即自动转入 ok——无需人工干预。

3. 环境差异声明仍然有效：hydro2 的生产统计结论不变；本容器第二轮以 `difficultyMinPriorEvents=1` 口径激活难度链路，其结论适用于该口径。

## 九、复现方式

```bash
# ① 仓库单元测试
cd /home/leeson/work/Hydro && node -r @hydrooj/register test/rating-v2.spec.ts

# ② 打包（宿主机）
cd packages/hydrooj && npx esbuild src/lib/rating-v2/shadow-replay.ts \
  --bundle --platform=node --format=cjs --packages=external \
  --outfile=/tmp/rating-v2-shadow-bundle.js
docker cp /tmp/rating-v2-shadow-bundle.js hydro:/tmp/   # runner 见容器 /tmp/rating-v2-shadow-runner.js

# ③ 容器内回放——默认口径 / 自适应口径（难度门槛=1）
docker exec hydro sh -c 'cd /tmp && NODE_PATH=/root/.hydro/dev-releases/20260917001855/node_modules \
  /root/.nix-profile/bin/node /tmp/rating-v2-shadow-runner.js \
  "{\"write\":true,\"poolId\":\"shadow-adaptive\",\"refDomain\":\"exam\",\"difficultyMinPriorEvents\":1}"'

# ④ 容器内盘点（audit，需显式传全参数，见 §四.2）
#    /tmp/rating-v2-audit-bundle.js + /tmp/rating-v2-audit-runner.js

# ⑤ 撤销影子数据
# mongosh: db.ratingv2_shadow.deleteMany({poolId:'shadow-adaptive'})   # 或 'shadow-trial'
```

容器内现存产物：`ratingv2_shadow` 两池（**shadow-trial 1,159 条**默认口径 / **shadow-adaptive 2,071 条**自适应口径；第一轮的 shadow-diagnostic-lowgate 已清理）、`/tmp/rating-v2-{shadow,audit}-bundle.js` 与对应 runner、验证脚本 `/tmp/{verify,verify2,verify3,spotcheck,probe-*,overlap*}.js`。
