## 0. 执行摘要

本次改造的目标不是把学习记录全部换算成竞技 Rating，而是建立三个相互隔离、又能够在产品层组合的系统：

1. **学习成就**：反映学生已经完成的学习任务。普通练习、作业、课程、比赛及赛后补题中的有效学习成果可以进入这一系统。
2. **比赛能力**：只依据经过认证的限时个人比赛，及其有效比赛窗口内的提交结果更新。提供内部能力估计、公开 Rating、固定分段的用户等级。
3. **题目比赛难度**：只用相同可靠比赛范围内的学生表现进行统计标定。没有可靠比赛证据的题目保持“未标定”，不从日常提交通过率制造难度分。

排名页面保留“题目”“比赛”两项，但解释其不同含义：

- **题目**：学习成就折算分 `P`。
- **比赛**：公开比赛 Rating `R`、对应等级，并显示它折算的排名贡献 `C`。
- **综合 RP**：`P + C`，明确是学习与竞技的综合激励指标，不宣称是纯能力排名。

### 0.2 本轮修订结论与实施状态

建议支持 CF、洛谷同源题目的外部难度同步。CF 数值难度可以作为候选标尺或经过映射的先验；洛谷分级先保留原始标签，有足够独立重叠题后才学习宽分布映射。两者均不能直接等同于当前本地 Rating。外部难度是题目参考信息，不是导入外站用户 Rating，也不会把日常练习结果变成能力测量证据。

用户提出的“外部题目 → 用户能力 → 本地题目 → 再估计”可行，但需要一个固定锚点、带时间状态、每条观测只使用一次的统计模型。现有 CF 风格名次算法不读取题目难度；新增路线应以独立模型和标尺进行影子比较，不能在原 Rating 上叠加一笔做题加分。

## 1. 需求边界与非目标

### 1.1 三条不可放宽的业务边界

**边界 A：学习数据与测量数据分离。**  
学生在日常练习中提交一千次、完成课程、补完作业，都不能改变比赛能力和题目比赛难度。学习成果只改变学习成就及由其构成的综合 RP。

**边界 B：比赛时间以原始提交发生时间为准。**  
赛内提交、赛后才完成评测的结果可以纳入；赛后新提交即使带着同一个比赛 ID，也不能纳入。重测不改变原始提交时间。

**边界 C：字段、分值尺度和用途必须分离。**  
旧题目等级、新题目比赛难度、公开用户 Rating、综合 RP 不能共用一个字段，也不能互相直接代入算法。

### 1.2 本期不做

不从日常 AC 率推断能力；不把教师主观题目等级当作统计难度；不导入未经核验的外站用户 Rating；不声称本地 1600 等于 Codeforces 1600；不直接建设自由参数 2PL、多维知识追踪或自动作弊裁决；不以系统分数自动替代课程成绩。经核验的外部题目难度可按 §8.7–8.8 引入参考层；这是本轮新增范围，仍不能绕过比赛测量资格。

“限时”是可靠测量的必要条件，不是充分条件。比赛还必须有明确的独立作答规则、统一的计分条件和有效的数据审查。

## 3. 总体架构：三条计算链，一层公开投影

```text
原始提交、题目版本、比赛规则、参加者身份
                  |
           事实与资格筛选
          /                 \
学习成果事实                 认证限时比赛事实快照
     |                         /           \
学习成就账本             用户比赛 Rating     题目比赛难度
     |                       |                  |
成就原始量 A             内部能力 mu          难度 D + 证据状态
     |                       |
题目贡献 P               公开 Rating R / 等级
          \                 |
           \           比赛贡献 C
            \             /
                综合 RP
```

关键隔离要求：

- 学习成就计算不能导入新难度或能力模型作为权重。
- 现有 `hydro-local-cf-v1` 保持“名次 → 能力 → 难度”的单向链路。§8.9 的锚定模型使用独立 `ratingModelVersion`、`skillScaleId` 和代际，不能混合两套 delta。
- 正式顺序结算的难度观测只读取**赛前**能力及本场合规结果。§8.9 的联合历史重估属于单独标记的回溯分析，不能冒充当时的赛前预测。
- 综合榜读取已经发布的分项投影，不能反过来修改 Rating。
- 资格、算法、公开策略、综合计分分别有独立版本号。

## 4. 数据资格：使用正向认证，不只排除作业名称

### 4.1 三类独立判断

```typescript
isAchievementEligible(record, visibilityScope): Decision
isRatingContestEligible(contest, policySnapshot): Decision
isCalibrationObservationEligible(contest, participant, problem, records): Decision
```

上述为拟新增接口，不是现有 API。返回值至少包含：

```typescript
type Decision = {
  allowed: boolean;
  reasonCodes: string[];
  policyVersion: string;
};
```

建议的原因码包括：

`NOT_TIMED_CONTEST`、`HOMEWORK_OR_COURSE`、`UNSUPPORTED_RULE`、`NOT_CERTIFIED`、`OUT_OF_WINDOW`、`NON_OFFICIAL_ENTRY`、`PREEXPOSED`、`MISSING_TIME_EVIDENCE`、`UNFINALIZED_JUDGEMENT`、`INSUFFICIENT_FIELD`、`PRIVATE_NOT_RELEASED`。

管理员必须能看到逐项原因；不能只有一个难以解释的 `false`。

### 4.2 数据使用矩阵

| 场景 | 学习成就 | 用户比赛能力 | 题目比赛难度 |
|---|---|---|---|
| 普通练习正式提交 | 可计，遵守公开范围 | 不计 | 不计 |
| 作业，包括设置截止时间的作业 | 可计 | 不计 | 不计 |
| 课程、随堂练习、课程内题目提交 | 可计 | 不计 | 不计 |
| 未认证的比赛 | 可计 | 不计 | 不计 |
| 认证限时比赛中的正式赛内提交 | 可计 | 合格选手纳入 | 逐题检查样本资格后纳入 |
| 赛后补题 | 可计 | 不计 | 不计 |
| 比赛期间从普通练习入口提交，未绑定本场正式参赛身份 | 可计 | 不计 | 不计 |
| 虚拟参赛、个人自由开始计时 | 可计 | 首期不计 | 首期不计 |
| 出题人、测试账号、旁观或场外参赛 | 原则上不向其本人所维护题目发放成就 | 不计 | 不计 |
| 合法赛内提交的赛后完成评测 | 可计 | 计入最终快照 | 计入最终快照 |
| 合法赛内提交被赛后重测 | 随有效判定修正 | 按修订流程回放 | 按修订流程重估 |
| 比赛题目本身存在失效测试或评测异常 | 等待修复 | 暂停发布或剔除无效题后重算 | 无效题不拟合 |
| 仍在封榜或结果未获准公开 | 只在授权范围内显示，不能泄露到公开 RP | 可暂存，不能泄露到公开投影 | 同样受发布范围限制 |

“可计学习成就”不是无条件公开：私密课程、隐藏测试和受权限限制的成果不得通过总分或接口间接泄露。

### 4.3 首期比赛认证条件

建议新增 `ratingPolicy`，与已有 `rated` 兼容但不等同：

```typescript
type ContestRatingPolicy = {
  enabled: boolean;
  eventKind: 'timed_individual_contest';
  mode: 'synchronous';
  poolId: string;
  skillScaleId: string;
  ruleVersion: string;
  eligibilityVersion: string;
  approvedBy: number;
  approvedAt: string;
  minParticipants: number;
  resultRelease: 'manual';
};
```

首期必须同时满足：

- `rated === true` 且新 `ratingPolicy.enabled === true`。
- `eventKind` 明确为比赛，不能是课程、作业或训练任务。
- 赛制为经过验收的白名单：首期 `acm`、`oi`。
- 统一起止时间有效，个人身份参赛；首期不支持 `duration` 自选开始模式。
- 规则、题单、参赛池、赛制、允许的辅助方式在开赛前固定。
- 比赛结束、正式评测全部进入最终状态、异常处置完成、管理员确认结算。
- 合格有效选手至少 10 人，且名次结果不是全员完全相同。10 人是建议门槛，不是统计保证。

**旧 `rated=true` 只能产生“候选比赛”，不能自动取得认证。**

新比赛开赛后不得为照顾特定结果临时切换 Rated 身份。系统故障、泄题等应通过公开的取消计分流程处理，而不是直接改字段抹去历史。

### 4.4 边界场景

课程中组织了一次真正的限时考试，应当创建独立、经认证的比赛实体，将课程作为导航或关联信息，而不是把 `rule='course'` 放进白名单。

首期不支持的 `ioi`、`strictioi`、`ledo` 等赛制，并非永远不能评分；必须先完成最终结果、并列、时间窗口和重测语义的适配测试，再通过版本升级加入。

## 5. 时间、身份、题目版本：构造可信的比赛事实

### 5.1 唯一时间判据

对同步比赛：

$$
t_{\mathrm{begin}} \le t_{\mathrm{submitted}} < t_{\mathrm{end}}
$$

采用左闭右开的区间。截止时刻恰好收到的提交不纳入；平台提交入口和结算器必须执行同一规则。

新记录建议增加：

```typescript
type SubmissionProvenance = {
  submittedAt: string;           // 服务端接受正式提交的时间，UTC，毫秒精度
  submissionKind: 'normal' | 'pretest' | 'generate' | 'hack';
  participationMode: 'official' | 'virtual' | 'practice' | 'staff';
  contestId?: string;
  problemRevisionId: string;
  ingressVersion: string;
};
```

这些是拟新增字段。`submittedAt` 必须服务端写入，不接受客户端覆盖；重测必须保留它。

`judgeAt` 是评测时间，不能用于判断是否赛内。当前代码还通过特殊 `contest` ObjectId 区分自测和生成记录，迁移时要识别这些特殊记录，不可仅判断 `contest != null`。[S4]

### 5.2 历史时间恢复

历史提交可以将 `_id.getTimestamp()` 作为候选时间证据，但必须记录：

- `timeSource = 'objectId-second'`，承认只有秒级精度。
- 是否来自标准服务端创建路径，是否发生过导入、伪造时间或迁移重建。
- 原比赛边界是否精确到整秒。
- 是否能与原始日志、比赛 journal 对上。

边界位于某秒内部、又没有毫秒证据的历史提交应标记为时间不确定。不能用估计时间“补齐”资格，更不能使用评测完成时间替代。

### 5.3 同一 Rating 池的事件顺序

首期要求同一 `poolId` 的 Rated 比赛时间窗口不重叠，按 `(beginAt, contestId)` 稳定排序。

这样可以明确每场的赛前状态属于哪个已结算前缀。不同班同时考试，需要选择“同一场共同比赛”或不同池；不在首期引入重叠比赛的复杂历史状态合并。

未来支持个人计时，应单独认证，其窗口为：

```text
start = max(contest.beginAt, participant.startAt)
end   = min(contest.endAt, participant.endAt（如有）, startAt + duration)
```

但时间公式正确仍不足以保证试题泄露、不同时间段可比性等问题已经解决，因此不默认启用。

### 5.4 参加者集合

默认有效参赛者须满足：

- 身份是正式个人参赛者，不是测试、场外、虚拟、团队共用账号或出题维护人员。
- 至少有一次比赛窗口内的正式提交；WA、CE、TLE 等零分结果也算真实参赛。
- 没有已确认的违规、代做或违规协作；怀疑记录先进入人工审查，不能自动定罪。
- 没有已知的本场题目预先接触优势；事先独立解过其中题目的用户原则上场外参赛。

只报名但无任何有效赛内提交的用户记为 DNS，不更新 Rating。只在赛后补交的用户同样不能变成有效参赛者。

已有效参加比赛的学生，某题没有提交时，该题结果可以记为 0：测量事件是“在整场给定时间内是否完成此题”，而不是“只看选择尝试该题的人”。这些 0 来自比赛暴露和题单，不来自日常未做题记录。

题目未向该用户开放、被撤题或该用户存在特殊访问条件时，不得把缺失伪装成 0。

### 5.5 既往做题经历和重复题

建议采用以下保守默认值：

- 赛前已知对本场任一正式计分题取得 AC 的选手，不进入本场能力更新集合；因为总名次可能已被熟题优势影响。
- 难度样本进一步排除已知接触过该题同版本的用户。
- 同一用户对同一题目版本、同一测量场景，难度拟合最多使用第一次合格观测，不能靠重复参赛增加样本量。
- 跨域引用、复制题应维护来源和规范题目 ID；普通版本修订不自动视为全新题目。

“平台没有记录到做过”不等于“现实中一定没见过”。比赛认证仍需组织者声明试题条件，并保留事后取消计分的通道。

### 5.6 事实快照不是现成排行榜截图

从原始提交重建有效 journal，使用赛制适配器计算结果：

- ACM：按合规记录计算通过数和罚时。
- OI：按该赛制定义选取最终计分提交，不能擅自换成历史最高分。
- 后续 IOI 类：只有明确其最高分、最后提交等规则后才能接入。
- 二元难度结果使用**该赛制最终计分结果中的满分通过**，而不是“曾经出现过任意一条 AC”。

不得直接读取混有日常记录的题目最高状态，也不得直接使用当前前端封榜显示值作为真实最终结果。现有 `RULES`、`stat`、`ranked` 可以复用，但必须在过滤后的 journal 上运行，并核对排序键、并列和 UI 一致性。[S5]

## 6. 内部能力、公开 Rating、能力等级的分工

| 概念 | 建议字段 | 含义 |
|---|---|---|
| 内部能力 | `competitionAbility.mu` | 本地比赛模型的连续 Rating 状态，用于后续计算 |
| 证据状态 | `competitionAbility.evidenceStatus` | `unrated`、`provisional`、`rated`、`stale`；描述证据，不是另一种能力值 |
| 公开 Rating | `competitionProfile.rating` | 发布策略处理后的整数分 |
| 能力等级 | `competitionProfile.tier` | 按固定 Rating 区间映射，不能按用户排名百分位决定 |
| 综合排名贡献 | `rpV2.contestContribution` | Rating 在综合榜中折算出的分数，不回流进能力模型 |

公开映射首期建议：

$$
R=\operatorname{round}(\max(0,\mu))
$$

没有任何有效历史时 `R = null`，显示“未评级”，不能把初始先验 1500 当成学生已经获得的能力等级。

首期不复制 AtCoder 的新人扣分与低分指数映射，也不声称有精确的贝叶斯能力方差。`provisional` 只是证据标签；未经过验证的启发式数值不能命名为 `sigma` 或“95% 能力置信区间”。

现有名次模型对长期未参赛只显示最后更新时间或 `stale` 标签，不自动扣减能力或成就。§8.9 的候选动态模型允许随时间增加能力不确定性，其均值不会仅因时间流逝而自动增长或扣减。

| 公开 Rating | 建议显示 |

暂定用户同时显示“暂定”，不通过高等级称号掩盖样本不足。旧的 RP 分位 `level` 保留为旧字段，能力等级必须另起名称。

## 7. 用户能力算法：本地 CF 风格，而非宣称复制 CF

CF 的公开说明采用期望名次、几何平均目标名次、二分反解目标 Rating 等步骤；当前仓库也有对应实现。[S3][S8] 本方案复用这条清晰路径，但定义独立版本 `hydro-local-cf-v1`。

### 7.1 赛前状态

新用户的内部先验均值建议为 `mu0 = 1500`。这只是本地标尺的起点，不是学习成绩、旧 RP 或外站分数的映射。

成熟和新用户都使用同一场开始前的状态快照。不得逐个更新后再拿更新结果计算下一个人。

### 7.2 排名及期望名次

正式有效参加者共 `N` 人，按赛制最终成绩排序。占据第 `a` 至 `b` 个位置的并列组选手，模型名次为：

$$
r_i=(a+b)/2
$$

对手 `j` 优于 `i` 的概率：

$$
p_{ji}=\frac{1}{1+10^{(\mu_i-\mu_j)/400}}
$$

期望名次：

$$
s_i=1+\sum_{j\ne i}p_{ji}
$$

目标名次及目标 Rating：

$$
m_i=\sqrt{r_i s_i}
$$

$$
1+\sum_{j\ne i}\frac{1}{1+10^{(R_i^*-\mu_j)/400}}=m_i
$$

目标值 `R_i*` 是向既有状态折中的更新目标，**不能包装成未经修正的“纯单场表现”**。

### 7.3 本地更新规则

初步变化：

$$
d_i=(R_i^*-\mu_i)/2
$$

按已批准的 D5 和影子实现，令 E 为赛前已有至少 5 场有效历史的成熟选手集合，采用成熟组中心化、Tanh 软饱和、新人零和豁免：

$$
\bar d_E=\frac{1}{|E|}\sum_{i\in E}d_i,\qquad
z_i=\begin{cases}d_i-\bar d_E,&i\in E\\d_i,&i\notin E\end{cases}
$$

$$
v_i=200\tanh(z_i/200),\qquad
\bar v_E=\frac{1}{|E|}\sum_{i\in E}v_i
$$

$$
\Delta_i=\begin{cases}v_i-\bar v_E,&i\in E\\v_i,&i\notin E\end{cases},\qquad
\mu'_i=\mu_i+\Delta_i
$$

其政策含义是：

- 在内部浮点误差范围内，成熟组变化量合计为 0；新人不参与两次中心化。没有成熟选手时两次均值均按 0 处理。
- 200 是中间 Tanh 输出的软饱和参数；成熟组再次中心化后，最终绝对 delta 可能超过 200，不能写成硬上限。
- 若未来需要严格的 ±200 上限，应另立算法版本并验证，不能把初稿的统一缩放规则与现有 Tanh 规则混用。
- 零和使成熟组保持相对尺度，不提供“整个群体同时成长”的识别能力。
- 全员完全并列、人数不足或输入无法求解时，整场不更新、不增加有效定级场次。

保留一份基于原始 CF 风格算法的离线基线用于比较，但生产只能启用一个明确版本，不能混合不同修正规则。

### 7.4 数值与输入约束

二分求解必须动态扩展包围区间并验证两端符号；不能固定搜索区间后把边界当成解。目标名次必须处于有效开区间 `(1, N)`；若浮点下溢把极端分差压成端点，应进入数值诊断，而不是把某个有限边界宣称为唯一解。

必须处理 NaN、Infinity、重复 uid、人数不足、非法名次和 sigmoid 溢出。内部保留浮点精度，只在公开层取整。数值失败返回 `unrated_reason` 并阻止本场发布，不发布部分用户的成功结果。

### 7.5 冷启动与可信度

首期状态建议：

- 无有效比赛：`unrated`。
- 1–4 场：`provisional`。
- 至少 5 场：可以解除定级标签，但还必须检查 Rating 池是否具有足够连接、不是长期只有同一小撮账号对赛。
- 建议池级公开门槛：至少 20 名不同实名或可信校内身份的有效用户，且比赛图形成可比较的连通主体。人数不足时保留试运行标志。

五场并不是精度证明。它只是最低定级门槛，仍需展示参赛次数、最近参赛日期和本地标尺说明。

### 7.6 本地相对能力的限制

这个首期模型测量的是**在指定比赛池中的相对竞技能力**，不是完整课程掌握程度。一个班全体一起进步而名次不变，仅靠相对名次无法识别共同进步。

因此：

- 同一池内部可以排名；无共同证据的不同池不能直接合并分数。
- 共同题目可以帮助诊断，但当前排名模型不会自动完成跨池换算。
- 要建设跨班、跨域统一能力池，应组织共同的认证比赛或引入独立验证的标尺连接方案。
- 不为了迎合“大家都在进步”而定期向所有人无依据注分。
- 未来若需要测量绝对成长，应另建锚定测评模型，不让综合 RP 冒充该模型。

本轮建议以 §8.9 的动态锚定模型探索相对于稳定题目参考集的成长。其可解释性仍依赖锚点稳定、场景相容和人群适用范围，不能宣称测到了无条件的绝对能力。

## 8. 题目比赛难度：从赛前能力和赛内结果估计

### 8.1 标尺和语义

建议使用本地 `skillScaleId` 对应的原始难度 `D`：

$$
P(Y_{u,p}=1\mid\mu_{u,\mathrm{before}},D_p)
=\frac{1}{1+10^{(D_p-\mu_{u,\mathrm{before}})/400}}
$$

这里 `Y=1` 指在规定比赛场景中，按最终计分规则满分通过。能力等于难度时，通过概率为 50% 是模型定义与待校准目标，不是所有现实人群中保证成立的事实。

CF 的题目难度公开说明也限定在典型比赛场景并使用近似含义。[S9] 本地模型是否校准良好，仍需用本地留出比赛验证。

### 8.2 可用观测的附加门槛

除第 4、5 节外，每条难度观测必须满足：

- 学生赛前已有至少 5 场有效比赛历史，并且其池处于可比较状态。
- 只能使用赛前内部 `mu`，不能使用公开取整值、新人折算值或赛后 Rating。
- 同题、同版本、同场景对同一学生去重。
- 题目版本、正式题单和最终判定可追溯。
- 包含全部合格、确实获得本题作答机会的有效参赛者，而不只包含给这道题提交过代码的人。

这意味着系统冷启动前几场可以建立用户 Rating，但多数题目尚不能标定。不能拿这些学生后来变稳定的 Rating 回填早期观测，冒充当时已知能力。

### 8.3 使用有先验约束的 1PL 估计

初版固定斜率，不拟合每题区分度：

$$
a=\ln(10)/400
$$

没有实证难度时，可以采用统一的计算先验：

$$
D\sim\mathcal N(1500,600^2)
$$

先验只是求解约束，不是对外发布的难度，也不是来自日常提交的学习证据。

求最大后验点估计：

$$
\hat D=\arg\max_D\left[
\sum_u \left(y_u\log p_u+(1-y_u)\log(1-p_u)\right)
-\frac{(D-1500)^2}{2\cdot600^2}
\right]
$$

每次重估使用固定初始先验和去重后的全部合格观测，或使用已证明等价的增量算法。**不能把上次后验再当先验，同时重复加入全部旧观测。**

该一维目标可用稳定的一维求解器求解；应验证收敛并输出诊断，不把固定迭代次数当作统计精度保证。

### 8.4 不确定性及发布门槛

条件标准误可用局部曲率近似：

$$
SE_{\mathrm{conditional}}
=\left[a^2\sum_u p_u(1-p_u)+1/600^2\right]^{-1/2}
$$

必须命名为“给定赛前能力和模型假设下的条件标准误”。它没有涵盖用户能力估计误差、同场相关性、熟题、模型不适配等因素，不能单独当成完整置信区间。

建议状态如下：

| 状态 | 建议规则 | 用户显示 |
|---|---|---|
| `unrated` | 没有合格比赛观测 | 未标定 |
| `insufficient` | 不足 20 个不同有效学生，或正例/负例任一不足 3 | 证据不足 |
| `provisional` | 至少 20 人、正负例各至少 3、条件标准误不超过 150，且通过拟合诊断 | 约 1500（暂定） |
| `rated` | 至少 50 人、至少两个独立合规测量场次或另有留出验证，诊断通过 | 1500，附证据入口 |
| `invalid` | 数据失效、版本无法确定或模型明显不适用 | 暂停标定 |
| `extreme` | 全员通过/全员未通过或处于不可支撑的外推区域 | 暂不提供普通点值 |

这些阈值均是首期建议。多场次数据必须满足相同测量场景和新样本要求，不能用同一批学生反复做同一题凑数。

全通过、全失败即使在先验下可以算出有限后验，也不应因此发布一个普通难度分。没有观测时不显示 0；0 可能是有效分值，不能兼任缺失值。

### 8.5 题目显示与旧字段

建议在独立校准集合保存完整状态，在题目对象上只保留当前授权可见的轻量投影：

```typescript
type ProblemCompetitionDifficulty = {
  raw: number | null;
  display: number | null;
  status: 'unrated' | 'insufficient' | 'provisional' | 'rated' | 'invalid' | 'extreme';
  skillScaleId: string;
  contextId: string;
  problemRevisionId: string;
  distinctUsers: number;
  independentContests: number;
  conditionalStdError: number | null;
  computedAt: string;
  generationId: string;
};
```

建议对外以 100 分为粒度显示，内部保留原值。很低的难度可以显示“低于 800”，不强制把所有基础题改写成 800；极高值也不靠裁剪假装已可靠标定。

旧 `difficulty` 可保留为“教学分级（旧）”，但不能继续被标注为新统计难度。日常通过率可以改变旧展示逻辑，却绝不能改变本节的新字段。

### 8.6 复用、场景差异与拟合失真

同题在 60 分钟和 180 分钟比赛中的表现，不能无条件合并。首期先定义有限的 `contextId`，包括赛制、统一时长方案、作答辅助规则等。题目存在多个场景时显示明确场景的结果，不暗中平均成一个数。

同一题目版本有新样本时，合并去重观测重新拟合，而不是直接对难度点值做人数加权平均。

固定斜率 1PL 在能力集合固定时，点估计主要由通过人数决定。因此还必须检查分数段实际通过率、反向表现、异常残差和留出预测；“算法收敛”并不代表“题目符合模型”。

### 8.7 外部难度兼容：先核验同题，再连接标尺

“兼容”分为三个层次：能够保存和展示外站原始难度；能在本地模型中作为有不确定性的先验；经独立验证后能成为连接标尺的参考锚点。完成前一层不自动满足后一层。

| 外部来源 | 原值含义 | 建议接入方式 | 不能据此声称 |
|---|---|---|---|
| CF Problem Rating | 题目数值难度；具体题目可能缺失，比赛条件和参加人群与本地不同 | 保存原始 rating、来源和时间；映射后作为候选先验，筛选参考锚点 | 本地 Rating 与 CF 用户 Rating 已等价，或缺失值等于 0 |
| 洛谷难度 | 有序分级，官方明确带有主观判断，仅作训练参考，当前定义可能调整 [S12] | 保存原始类别及体系版本；有独立重叠题后学习各类别的宽分布 | 相邻级别等距，或“某颜色必然等于 CF 某分” |
| 洛谷转载的 CF 题 | 同一上游题目的另一展示入口，可能同时存在洛谷分级 | 归并到 CF 规范身份，保留两个来源字段 | 两个站点提供了两份独立统计证据 |
| 来源不明、改编题、缺少难度值 | 无可核验基准 | 仅保留待匹配信息或无外部参考状态 | 根据标题猜到原题后即可继承分数 |

本轮查阅的洛谷官方页面使用“入门、普及-、普及、普及+/提高-、提高、提高+/省选-、省选/NOI-、NOI/NOI+/CTS”八个等级，并注明临时定义。旧调研文档中的标签名称不能写死为同步协议；“暂无评定”也不是最低难度。[S12]

**题目身份必须明确：**使用上游题号和链接，例如 CF 的题集类型、`contestId + index`、洛谷 `problemId`，关联到本地 `(domainId, canonicalProblemId, problemRevisionId)`。核对题意、约束、输入输出、计分规则和测试版本；无法取得外站测试数据时记录这一证据限制。纯翻译可成为同题候选，但阉割数据、改约束、改成部分分题不能自动认作等价。标题、文本相似度只用于生成审核候选。

仓库现有 `packages/vjudge/src/providers/codeforces.ts::getDifficulty()` 会把 CF 数字压缩为旧的 1–10 分级，这是有损映射，不能从旧 `difficulty` 反推原始 CF Rating。新增同步需读取、保存外站原值，禁止覆盖旧字段。

**标尺连接使用独立训练证据：**对场景相容、跨难度段的共同题，先拟合简单的正斜率映射，例如：

$$
m_p=f(D_p^{\mathrm{CF}})=\alpha+\beta D_p^{\mathrm{CF}},\qquad\beta>0
$$

共同题的本地校准必须来自合格比赛，并保留本地估计误差；不能把这些点当无误差真值做机械回归。映射在未参与拟合的题目、后续比赛和不同年级上检验，记录覆盖范围与误差。小样本先用简单映射或保持参考展示，不能靠高阶曲线“拟合成功”。超出覆盖范围只标外推，不给正式等价承诺。

若新模型直接选用“CF 参考坐标”，恒等映射只是坐标与初始化选择，仍须验证本地通过概率；它不证明 θ 等于 CF 官方用户 Rating。把外站分数映射到现有本地相对标尺，只改善题目先验，不会让旧名次算法自动识别整体成长。

洛谷类别若需数值化，使用独立共同题估计每级的分布，例如 `D | category ~ N(m_category, τ_category²)`，只约束类别中心总体有序，允许分布重叠。类别宽度、映射误差和场景差异均进入不确定性；数据不足时不提供精确数值映射，也不预先制定“入门=800”等固定对照表。

### 8.8 外部同步脚本与锚点生命周期（待实现）

建议新增 `rating-v2-sync-external`，职责仅为“同步来源快照、关联候选、输出差异”。能力重算和公开切换使用独立回放任务。

1. **来源与匹配清单。** 从已有远程来源 ID、引用链或管理员确认的映射开始，输出已确认、歧义、改编、缺失四类结果；不按标题批量强配。
2. **采集原值。** CF 优先使用公开 API `problemset.problems` 的题目标识与可选 `rating` [S11]；洛谷仅接入经核实可用的公开渠道或授权导出，未确认有稳定公开 API 前不绑定内部接口。读取失败、限流、字段变更保留上次快照并报告，不能把异常响应当作难度清零。缓存、限速和重试按来源约定实现，不绕过访问限制。
3. **保存不可变快照。** 默认 `write=false` 出报告；显式写入也仅新增外部快照及候选映射，按内容哈希幂等。源值、匹配变更和映射变更均可追溯。
4. **评估并固定锚点版本。** 选用版本一致、场景接近、覆盖能力范围且无熟题污染的参考题，固定 `anchorSetVersion`、`mappingVersion` 和源快照。未知是否学过的公开题不能仅凭“同步成功”通过测量资格；锚点覆盖不足时补充受控测评或保持暂定。
5. **变更走新代际。** 外站后来改分、题目改版、映射修订、锚点失效均只产生候选版本；通过影子差异检查后才重放并切换。不能每次抓取即移动正在使用的标尺，也不能为消除残差而偷偷修改锚点。

建议最小记录字段：

```text
source, sourceProblemId, canonicalSourceId, sourceUrl
rawValueKind: numeric | ordinal | missing, rawValue, sourceScaleVersion
sourcePublishedAt: nullable, fetchedAt, payloadHash, parserVersion
domainId, canonicalProblemId, problemRevisionId, matchStatus, matchEvidence
mappingVersion, skillScaleId, contextId, mappedMean, mappedUncertainty
anchorRole: referenceOnly | softPrior | fixedAnchor, anchorSetVersion
availableAt, generationId
```

`fetchedAt` 不是题目难度在历史上可得的证明；`sourcePublishedAt` 不明时，以本地首次留存时间作为最早可证明的本地可用时间。用今天的外站分数分析旧比赛，应标记“当前外部基准下的回溯分析”，不能据此声称当年的前瞻预测准确。

保留三个不同值：`externalRaw`（外站原值）、`mappedPrior`（进入本地标尺的先验）、`localPosterior`（本地比赛估计）。普通外部题使用软先验，允许本地证据使估计偏离；只有审查过的参考子集在一次标定版本中固定。没有本地样本时只能展示“CF 参考难度”或“洛谷分级”，本地状态仍为未标定；全对/全错的本地证据也不能借外部原值升级为本地 `rated`。

外站通常不会随分数提供可直接使用的完整统计方差。`mappedUncertainty` 必须标明是映射残差估计或策略性的保守假设，不能写成外站官方置信区间，也不能设为 0 或伪造外站样本数。

### 8.9 动态锚定能力与受约束迭代（候选模型）

建议候选版本名 `hydro-anchored-1pl-dynamic-v1`。用 θ 表示它的能力，继续用 μ 表示现有名次模型能力；两者分别保存、分别验证。比赛的满分成功/失败事实可复用，资格、场景和满分判定按第 4–5 节处理，不加入普通练习记录。

#### 8.9.1 先固定标尺和参考题

当概率只依赖 `θ-D` 时，同时给所有用户和题目加同一常数，不改变任何预测；如果斜率也可自由变化，还会出现尺度不确定。因此，一次拟合中固定 `a=ln(10)/400`、来源映射和参考题子集的 D，普通题才允许根据数据更新。不能同时自由调整全部用户、全部题目、外部映射和概率斜率。

每个发布分量必须通过合格用户—题目观测连接到可信锚点，并覆盖拟发布的能力范围。只有先验而没有锚点连接的用户群，保持独立本地标尺或未锚定状态，不能伪装成可比较的 CF 参考分数。共享标尺也不自动授权跨池合并私密观测。

“固定锚点”是一次估计中的坐标约束，不代表题目无误差。用保留的参考题和新学生检测其偏差；通过替换部分锚点、扰动锚值的敏感性分析估计影响。失效锚点只在新版本中退出或改为软先验，同版内不同时把同一题当固定标尺和自由拟合目标。

#### 8.9.2 正式运行优先采用按时间推进的估计

每名学生每个比赛时点有自己的 θ，采用最简单的零均值随机游走候选模型：

$$
\theta_{u,t}\mid\theta_{u,t-1}\sim
\mathcal N(\theta_{u,t-1},q\,\Delta t),\qquad q\ge0
$$

`Δt` 使用固定单位（例如天），`q` 的单位是分数平方/天，在训练数据上选择并按版本冻结。同一用户重叠比赛不作为两个独立时间步；沿用比赛窗口资格规则。初始状态使用宽先验，具体宽度随标尺和训练验证确定，不把所有人的真实水平先定为 1500。

这一模型允许证据支持的上升和下降；时间流逝只增加预测不确定性，不默认学生每月进步多少分。没有新比赛时不凭空改变公开均值，保留最近测量时间和暂定/过期标记。

每场执行顺序：

1. 读取当时已可用的锚点版本和已校准题目 D，固定为赛前输入；新题或只有未经验证分级的题不能负责给新人定标。
2. 从该用户过去的有效比赛推导赛前分布 `q⁻(θ)`，保存其输入时间截止点、均值和方差。预测本场只能使用该分布。
3. 赛后用合格校准题的本场结果更新 `q⁺(θ)`。更新目标由本场逐题 Bernoulli 似然和一次预测先验构成；题目 D 有明显不确定性时应积分或传播该误差，不能当固定真值。
4. 为普通待标定题生成观测时，仍使用步骤 2 的赛前分布，不能使用已经吸收该题结果的步骤 3 的能力。保持赛前至少 5 场这一初始资格门槛，并检查锚点覆盖和估计不确定性；仅有 5 场不保证测量可信。
5. 难度以符合版本、场景、去重条件的观测重新拟合；结果经检查进入后续比赛可用版本。本场中间结果不反复回灌本场能力，也不在前瞻评估中使用未来版本的 D。

考虑能力估计误差时，题目预测应使用：

$$
P(Y_{u,p,t}=1)=\int\sigma\!\left(a(\theta-D_p)\right)
q^-_{u,t}(\theta)\,d\theta
$$

其中 `σ` 为 logistic 函数。不能简单把不确定的能力均值当成已知真值后，还把原 §8.4 的条件标准误当完整误差。数值积分、参数更新和不确定性传播是新增实现，现有纯函数尚不具备这些能力。

新模型不做成熟组零和：稳定参考题提供了共同进步的观测依据。也不把同场的 CF 名次似然、已由这些题得到的 Rating 先验和逐题结果再重复相乘；首版只使用逐题测量证据，旧名次模型用于对照。

#### 8.9.3 离线联合重估允许迭代，但要优化同一个目标

用户提出的交替更新可以在冻结的训练集上实现。令 j 表示同一标尺中已经区分题目版本和场景的规范题目，A 表示固定锚点集。候选最大后验目标为：

$$
\mathcal L=\sum_{(u,j,t)\in O}\log\operatorname{Bern}
\left(y_{u,j,t};\sigma(a(\theta_{u,t}-D_j))\right)
-\sum_{u,t>1}\frac{(\theta_{u,t}-\theta_{u,t-1})^2}{2q\Delta t}
-\sum_u\frac{(\theta_{u,1}-m_0)^2}{2s_0^2}
-\sum_{j\notin A}\frac{(D_j-m_j)^2}{2\tau_j^2},
\quad D_j=A_j\ (j\in A)
$$

此式针对固定 `q>0`、正时间间隔；`q=0` 的静态基线应将时间状态合并处理，不能除以 0。`m_j, τ_j` 来自冻结的外部软先验或统一宽先验，不来自上一轮后验。超参数在训练/调参阶段确定，评估期冻结。

可依次固定 D 优化各人的历史能力轨迹，再固定轨迹优化非锚点 D，直到目标和参数变化达到预设容差，或到最大迭代次数。记录目标值、收敛状态、锚点残差和对初值的敏感性。每轮重用的是同一份数据的同一个目标函数，不能把同一条答题记录累计成多个样本；不能“上轮后验作为新先验 + 全部旧数据”重复增信。

联合估计本身并非无效循环；没有外部约束、没有时间状态、反复累加证据才会制造漂移和虚假精度。冻结锚点后，优化仍可能暴露场景偏差、熟题、题目间依赖和单维模型不适配，不能用收敛替代验证。

使用完整训练历史得到的 `θ(u,t | 截止 T 的全部训练数据)` 属于**平滑后的回溯能力**，可以在上述联合目标中解释历史数据，但不是时点 t 当时可得的能力。它与正式路径的赛前过滤分布分开存储，不能覆盖旧的预测快照，也不能把这种回溯重估的拟合误差报告成未来预测误差。不能把训练全集末端的 D 无条件套回每场历史，再声称完成了因果回放。

按更正后的事实逐场重放同一历史前缀仍属于 filtering；只有使用后续观测来推断较早时点状态才标为 smoothing。两类修订都保留旧代际，避免将正常事实更正与未来信息泄漏混为一谈。

建议先实现外部同步和按时间推进的影子模型；只有独立验证显示有收益时再增加联合重估，避免首版同时承担两套推断复杂度。新模型通过验收前，公开比赛贡献仍读取原模型的已发布版本，不能自动混合两种能力分。

### 8.10 用户成长会不会使历史题目难度失真

**会，但历史数据并不天然无效。** 关键是使用当时的能力、保留当时的测量条件，并识别当时能力估计本身的误差。

| 使用方式或变化 | 可能的偏差 | 处理 |
|---|---|---|
| 用今天的能力解释过去的失败 | 把当年正常的失败误认为高水平也做不出，使题目偏难 | 使用当时赛前状态；回溯分析使用整条动态轨迹，不用一个终态值覆盖所有年份 |
| 全班一起成长，名次几乎不变 | 现有零和模型 μ 不升，解出率却升，题目容易被估得越来越简单 | 用稳定外部锚点测量共同成长；仅靠历史名次无法识别 |
| 学生突然进步，赛前能力尚未跟上 | 新一场的成功被归因于题目变简单 | 动态不确定性、跨场检验、足够独立样本；对大残差暂缓正式标定，不能用本场赛后分直接补洞 |
| 公开题见过、训练重点改变、比赛时间变长 | 题目原值不变，但本地成功条件改变 | 熟题排除，分场景/版本，按年级与知识领域检查残差 |
| 能力轨迹估计合理、题目和场景稳定 | 旧观测仍可提供有效证据 | 保留历史，无需仅因年代久就丢弃 |

例如，假设一批学生当年能力均为 1200，某题通过率约 50%；按未加先验的模型，D 约为 1200。若他们后来成长到 1800，却用 1800 回填同一批旧结果，拟合会把 D 推到约 1800，凭空抬高约 600 分。现有赛前 μ 设计避免了这种直接回填，但不能解决零和标尺看不见群体成长、赛前评分滞后等问题。

默认先使用动态能力与一致场景下的全部合格历史，按学期检查锚点残差、分段通过率和新旧样本差异。发现题目版本变化应新建版本；发现教学环境造成稳定场景差异应拆分 context 或暂停统一标定，不能无限更新同一题 D 来掩盖原因。

仅在训练验证支持时再试时间权重 `w=2^(-ageDays/halfLifeDays)`，半衰期不预设为“统计真理”。它改变了所估计的时间范围，应显示窗口与策略版本；同时报告原始人数和有效样本量 `n_eff=(Σw)²/Σw²`，正负例覆盖仍单独检查。时间衰减不会修复错误的能力标尺，也不能用大量低权重旧样本凑足发布人数。联合估计有相关观测时还需按用户/比赛评估误差，不能只靠这一公式。

### 8.11 外部参考、暂定估计与正式发布分开

外部原值和标签可按授权展示来源；本地正式分数仍需满足原有学生数、正负例和场景要求。锚定模型还需通过连接覆盖、锚点稳定、映射适用区间、能力不确定性和按比赛时间留出的验收，不能仅凭 `SE≤150` 发布。

题目页建议并排显示“CF 原始参考 1600（来源快照日期）”“本地比赛难度约 1700（暂定，场景与样本日期范围）”；用户页明确是“本地比赛 Rating”还是“CF 参考标尺下的能力估计”。数字仅为展示示例，不预设二者换算关系。

更换能力模型会影响段位和综合贡献，不能直接把 θ 填进旧 `R/2800` 折算并沿用旧含义。须比较新旧分布、单独确定映射与 `rpPolicyVersion`，在完整新代际中切换；没有通过验收则继续作为影子指标。外部锚点误差或模型错误修正与学生真实成长应在曲线上标明不同原因。


## 9. 学习成就：累计成果，不再推断能力

### 9.1 计分目标

学习成就回答：“学生完成了多少被认可的学习任务？”

首期建议不采用统计难度加权，也不读取旧 `difficulty` 的动态值。这样能够同时避免：

- 千分制难度误入奖励权重造成单题奖励暴增。
- 同一道题因为其他学生后续表现变化，让已完成者的成就反复变化。
- 新题、课程题因没有比赛难度而无法获得学习奖励。
- 学生成就随提交次数、重复做同题而无限增加。

### 9.2 规范题目与去重

建立 `achievementKey`，作为一个域内同一学习任务的稳定标识。

普通重测、测试数据修复、跨课程重复引用以及同一来源题目的重复分发，默认不生成新的成就。真正独立的新任务可由有权限人员创建新 key，并记录原因。

不能仅按文本相似度自动合并题目；错误合并会吞掉真实成果。对于历史复制题，应先做候选清单、人工确认和可回退映射。

默认唯一键：

```text
(domainId, uid, achievementKey, achievementPolicyVersion)
```

不同域的公开学习成果默认不相互泄露或直接累加。全站汇总需要单独授权与去重策略，不作为本期默认行为。

### 9.3 成就原始量 A

对用户 `u` 和规范题目 `p`：

- 在授权计分范围内存在有效 AC：`a(u,p)=1`。
- 没有 AC，但有可靠、可归一化的部分分：`a(u,p)=0.5 × q(u,p)`。
- 其他情况：`a(u,p)=0`。

其中：

$$
q(u,p)=\max_{\text{该题有效记录}}\operatorname{clip}
\left(\frac{\text{原始得分}}{\text{该版本满分}},0,1\right)
$$

总学习成就：

$$
A_u=\sum_p a(u,p)
$$

因此，1 个单位表示一道完整完成的学习任务。100 道题各得 60% 且无 AC，折算成 `100 × 0.5 × 0.6 = 30` 个单位。

满分记录与 AC 状态不一致时，不擅自认定完整通过，先按部分分或异常规则处理。满分值不确定、NaN、Infinity、负分等记录不能进入归一化，必须有诊断输出。

### 9.4 部分分为何保留

“题目”现在表示学习成就，不再声称是 AC 数或纯能力。因此，部分完成获得有限奖励是可解释的。

为了避免用户把两者混为一谈，页面必须同时展示：

```text
完整通过：100 题
部分完成折算：12.5 个单位
学习成就总量：112.5 个单位
```

如果一个学生只有部分完成，其“通过”列可以为 0，但必须明确显示部分完成贡献；不能再让用户猜测分数来源。

### 9.5 更新与修正

正常新增提交只在该题成就有提升时改变账本。重复 AC、重复提交低分、再次参加同题比赛不额外加分。

合法 AC 被重测推翻、题目合并、确定违规或公开权限改变时，允许成就更正，但必须保留变更原因和前后值。不能承诺积分永不回退，否则错误判定无法纠正。

学习成果账本可以增量维护；公开 RP 可以批量刷新。必须分别显示“成果时间”和“榜单刷新时间”。

## 10. 综合排名计分：600 分学习 + 400 分比赛

### 10.1 原则

综合榜是一个透明的激励规则，不是统计模型导出的唯一正确排名。

建议初始权重偏向教学场景，同时保留明显的竞技贡献。原始成就、公开 Rating 和综合 RP 均可查看；用户能够分别按学习成就和比赛 Rating 排序。

### 10.2 “题目”贡献 P

建议使用：

$$
P(A)=600\frac{A}{A+200}
$$

其中 200 是半饱和点：完成 200 个学习成就单位，对应 300 分。

| 学习成就 A | 题目贡献 P |
|---:|---:|
| 0 | 0.00 |
| 5 | 14.63 |
| 18 | 49.54 |
| 100 | 200.00 |
| 200 | 300.00 |
| 442 | 413.08 |
| 1000 | 500.00 |

采用这一曲线的理由是起点为 0、单调、上限明确，且在当前讨论的数百题量级仍有可见增长。它不是线性计题，也仍有边际递减；原始完成量 `A` 必须始终公开。

其导数为：

$$
P'(A)=\frac{120000}{(A+200)^2}>0
$$

因此没有“做满多少题后突然归零”的硬上限。但题库规模若发生数量级变化，应通过新计分版本重新评审半饱和点，而不是在后台自动按当前第一名归一化。

### 10.3 “比赛”贡献 C

公开 Rating 为 `R`，有效比赛场次为 `n`。建议：

$$
q(n)=\min(1,n/5)
$$

$$
C(R,n)=
\begin{cases}
0,&R=\text{null}\\
400\cdot q(n)\cdot\operatorname{clip}(R/2800,0,1),&\text{其他}
\end{cases}
$$

解释：

- Rating 达到 2800 后，综合榜比赛贡献达到上限；原始 Rating 仍可继续提高。
- 暂定用户前 5 场逐步放开比赛贡献，避免一场比赛的初始位置带来过大的综合收益。
- 第 5 场之后不再因为场次增加而提高 `q`，不会长期变成“参加次数榜”。
- `q` 只作用于综合排名贡献，不作用于内部能力、不作用于公开 Rating、不作用于难度拟合。
- 无 Rating 时贡献为 0，含义是“没有可计入的比赛证据”，不是“能力等于零”。

**必须公开的取舍：**前 5 场即使 Rating 基本不变，综合贡献也可能增加。这是定级期的排名政策，不是能力提升。若后续认为该激励不适合实际用户，应在新综合政策版本中调整，不能在解释中回避。

### 10.4 总分及精度

$$
RP=P+C
$$

建议分别将 `P`、`C` 以十进制四舍五入保留两位，保存为整数“百分之一分”，然后相加得到总分：

```text
problemCents = roundHalfUp(100 × P)
contestCents = roundHalfUp(100 × C)
rpCents      = problemCents + contestCents
```

这样界面上的两个贡献相加严格等于总分。不得先用高精度总分排序、再只显示粗粒度整数而让大量“同分”用户实际次序无法解释。

相同 `rpCents` 使用并列名次；`uid` 仅作稳定分页顺序，不作为隐藏的排名优劣依据。能力榜按公开 Rating 排序，暂定状态单独标识或提供过滤。

### 10.5 示例：不同学习路径如何排序

以下均为公式算例，不是生产用户真实画像：

| 示例用户 | A | Rating | 有效场次 | 题目 P | 比赛 C | 综合 RP |
|---|---:|---:|---:|---:|---:|---:|
| 学习与竞赛均衡 | 200 | 1800 | 8 | 300.00 | 257.14 | 557.14 |
| 进阶竞赛型 | 100 | 2400 | 8 | 200.00 | 342.86 | 542.86 |
| 长期学习、未参赛 | 442 | 未评级 | 0 | 413.08 | 0.00 | 413.08 |
| 少量学习、高等级 | 18 | 2400 | 8 | 49.54 | 342.86 | 392.40 |
| 一次表现较好的新人 | 18 | 1700 | 1 | 49.54 | 48.57 | 98.11 |
| 100 题各得 60%、没有 AC | 30 | 未评级 | 0 | 78.26 | 0.00 | 78.26 |

这套权重会让大量学习成果能够超过“很少学习但竞技很强”的某些用户，同时让兼顾两者的人占优。这是显式的教学激励取向，而不是对谁能力更强的判断。

“600:400”只表示两项的贡献上限比例，不保证真实榜单的方差贡献也恰好为 60% 和 40%。上线前必须用历史可信样本检查实际贡献分布。

### 10.6 不进入新综合榜的项目

V2 默认不把置顶题解数、旧 `rpdelta` 或插件隐形加分加入总分。题解贡献可以保留在个人主页和独立贡献视图。

必须防止现有 `global.Hydro.model.rp` 扩展机制把新总分重新变成任意模块之和。[S2] 新综合榜使用固定版本、明确列出的分项注册表，不能仅靠遍历旧对象决定公式。

旧贡献和调整记录保留，不删除历史；只是明确不纳入 `rp-policy-v2`。

并排展示：

不要要求教师通过直接改 MongoDB 字段来恢复评分。管理操作应有权限检查、审计日志和幂等任务 ID。

### 12.2 事实与模型状态不能混为一个快照

`contest.fact_snapshot` 保存“发生了什么”，不把某一次重算得到的赛前 Rating 永久写死为事实。

`rating.evaluation` 保存“在某个模型和历史前缀下如何解释事实”。早期比赛被纠正时，新代际重新构造后续赛前状态；旧代际仍保留原状态，便于审计。

这避免出现“要求历史回放，却仍读取旧的赛前 Rating 快照”的自相矛盾。

### 12.3 必需版本号

```text
eligibilityPolicyVersion   数据资格规则
contestScoringVersion      赛制与并列规则
ratingModelVersion         用户能力模型
difficultyModelVersion     题目难度模型
skillScaleId               本地能力坐标系
contextId                  题目测量场景
achievementPolicyVersion   学习成就规则
rpPolicyVersion            综合折算规则
problemRevisionId          题目与测试版本
factRevision               比赛事实修订号
generationId               同一批公开结果的代际号
sourceSnapshotId           外部难度原值及取得时间
mappingVersion             外部标尺/洛谷类别映射
anchorSetVersion           本轮固定参考题集合
temporalModelVersion       状态转移、时间单位、参数与推断策略
```

这些版本不要求同时变化。例如调整综合权重，只需重建综合投影；不应重新拟合用户能力和题目难度。

锚定模型还需保存 `dataCutoffAt`、`informationAvailableAt`、`evaluationMode=filtering|smoothing`、训练/验证清单哈希及输入版本哈希。赛前 θ、赛后 θ、平滑后的 θ 必须可区分；未来证据修订只能产生新代际，不能覆盖当时发出的预测。

```typescript

  uid: number;
```

不要使用“读取值 `|| 1500`”的方式获取状态，因为 0 是合法值；使用显式空值判断或 `??`。

最低要求：

### 12.6 数据最小化

评分账本不需要复制源代码全文、IP、邮箱等敏感信息。保留记录 ID、结果、校验摘要、资格原因和版本即可。

原始代码访问沿用评测系统的权限；公开统计接口不得返回与解释分数无关的身份信息。审计记录及历史代际应定义保留策略，不能无限保存敏感内容。

## 13. 结算、发布、重测与回放

### 13.1 比赛状态机

```text
draft
  -> approved（开赛前认证并冻结规则）
  -> running
  -> ended_pending_judgement
  -> pending_review
  -> calculated（结果仅在暂存区）
  -> published
```

异常分支：

```text
任一未发布阶段 -> unrated / canceled
published -> revision_requested -> 新 factRevision -> 新 generation -> published
```

不能仅依据 `endAt < now` 自动发布。排队中的评测、系统错误、未完成重测和待审异常均应阻塞结算。

管理员手动发起发布之前，后台可以预计算，但必须保持“已计算”和“已公开”不同。

### 13.2 一次结算的固定顺序

1. 锁定池、检查当前历史前缀和政策版本。
2. 构造或读取不可变比赛事实快照，输出排除清单。
3. 从已确认的前序比赛状态取得所有人的赛前 `mu`。
4. 对过滤后的赛内 journal 计算最终结果和平均并列名次。
5. 使用赛前能力生成难度观测；成熟度也取赛前值。
6. 使用同一赛前能力计算本场所有用户的 Rating 变化。
7. 在暂存代际中写入用户状态、难度估计、学习成就更新及榜单投影。
8. 校验人数、重复键、数值范围、总分、数据版本及结果一致性。
9. 获得发布批准后，切换公开代际指针。
10. 发送一次结果通知，并保留可重试的任务状态。

第 5 和第 6 步可以在计算层并行，但都必须消费同一个赛前状态，不能相互读取本场结果。

### 13.3 幂等与并发

同一个事实版本和输入状态重复执行必须生成相同结果，重复请求不能再次加分。

建议使用每池串行 Worker、租约锁和带 fencing token 的写入约束；只靠一个可能过期的 Redis 锁不足以阻止旧 Worker 继续写。

如果部署环境支持跨集合事务，可以采用事务；如果不支持，使用“不可变暂存代际 + 完整性清单 + 单文档比较并交换公开指针”。不能假定当前 MongoDB 部署一定提供事务能力。

列表、个人行、排名计数和题目投影必须读取同一 `generationId`。指针切换完成前，前台继续显示上一份完整结果。

### 13.4 学习成就的增量刷新

高频日常提交不应触发所有比赛重算。

学习成就 Worker 只更新该用户该规范题目的账本，并重建受影响的 P 和 RP 投影，复用同一已发布比赛能力版本。榜单整体排名刷新时同样使用完整代际或具备一致性的物化视图发布机制。

能力和难度的变动只能来自合格比赛发布或其合法修订。

### 13.5 重测、取消资格和更正

如果修订只涉及某题学习记录，不影响任何有效比赛，重算对应成就即可。

如果一场已发布比赛的有效结果、题目、参加者或身份资格变化：

- 生成新的事实修订，不覆盖旧快照。
- 从该场之前的检查点开始，按时间顺序重放该池后续比赛。
- 重算后续用户状态及使用这些赛前状态的难度观测。
- 更新涉及的题目估计和综合投影。
- 输出受影响人数、题目数、Rating 变化范围和公开解释。
- 验收后一次性发布新代际；失败时保留旧公开结果。

不能只“减去被取消那场的 delta”，因为后续比赛的期望名次已经依赖先前状态。

### 13.6 历史重建与评估中的时间泄漏

回放历史时，要区分：

- **纠正后的历史**：在新事实版本下重建完整结果。
- **当时可知的历史**：只使用当时已经发布、已经可用的信息，用于离线预测评估。

未来发现的重测结果、未来成熟的用户能力、未来拟合的题目难度，可以用于修订历史档案，但不能冒充过去就已知道的预测输入。评估数据必须有 `availableAt` 或对应版本时间证据。

### 13.7 隐藏结果与发布顺序

尚未获准公开的比赛结果，不能通过用户新 Rating、新题目难度或综合总分间接泄露。

首期采用保守策略：同一池按历史前缀发布；前序比赛尚未释放，其后依赖该状态的公开更新暂缓。长期保密的考试应使用独立授权范围，不默认进入公共池。

### 13.8 计算规模、监控与失败告警

设单场有效人数为 `N`，二分迭代数为 `B`，逐题有效观测数为 `U_p`：

- 直接实现的 Rating 反解约为 `O(B × N²)`。
- 固定斜率的一维难度拟合约为 `O(B × ΣU_p)`，不扫描无关日常记录。
- 学习成就按受影响的用户—规范题目增量更新，不随每条普通提交重放比赛历史。
- 历史回放成本取决于受影响比赛前缀之后的全部事件，必须提供检查点和任务进度。

先在 30、100、300、1000 人等合成规模以及真实历史规模上做基准；这些是测试规模，不是当前生产人数。根据实测设置超时、资源预算和任务批量，不预先承诺毫秒级完成。

必须监控结算滞后、待评测记录、排除原因占比、数值失败、重复任务、前序发布阻塞、代际校验失败和异常 Rating 变化。错误应阻止发布并通知管理员，而不是自动换成默认分数继续运行。

### 14.3 接口草案

以下仅表示需要提供的能力，正式路由应遵循项目约定：

```text
GET  某域的综合榜、成就榜、比赛能力榜
GET  某用户的能力状态与已公开比赛历史
GET  某题目在指定标尺与场景下的难度状态
POST 管理员认证或撤销未开赛的 Rated 政策
POST 管理员预计算、审查、发布比赛结果
```

响应必须携带 `generationId`、政策版本和缺失状态，不能只返回一个数字。所有写入操作必须经过角色校验和审计；高影响的历史回放、取消计分建议增加二次确认。


## 15. 历史迁移：不洗掉学习成果，不伪造比赛证据

### 15.1 迁移前盘点

生成只读审计报告，至少统计：

- 各类比赛、作业、课程数量及 `rated` 使用情况。
- 比赛起止时间、赛制、个人计时、参加人数、封榜及结果公开状态。
- 提交时间证据的完整性、异常比赛 ID、自测和生成记录。
- 能否恢复原始正式身份、题单、评测版本和最终成绩。
- 日常成绩最高状态与比赛原始记录混用的情况。
- 旧 `difficulty` 的分布和异常值，但不据此推定具体榜单异常原因。
- 题目引用、复制和跨域关系，规范成就 key 的候选映射。
- 当前 RP、分项、等级、人工调整、置顶题解贡献的备份。

没有盘点结果前，不承诺能够给所有题目补出难度，也不宣称能够复原所有旧比赛。

### 15.2 历史比赛审核

历史比赛默认 `not_certified`。按证据分为：

| 类别 | 处理 |
|---|---|
| 赛内记录、时间、身份、最终计分均可恢复 | 可以申请进入历史 Rating 回放 |
| 比赛排名可核对，但题目版本或逐题记录不完整 | 逐项审核；可能仅支持能力回放，不支持难度标定 |
| 有最终榜单，但无法排除作业、课后更新或补题污染 | 仅保留历史展示，不进入模型 |
| 时间和身份来源不明 | 不进入模型 |
| 已确认作业、课程、虚拟或非限时活动 | 永不进入新模型 |

能够使用排名并不自动代表可以使用逐题结果；相反，某题不可标定也不必机械否决整场能力更新，前提是该场最终公平成绩可可靠重建。

### 15.3 迁移执行顺序

1. 备份旧 RP、分项、等级、规则配置和公开榜单快照。
2. 建立新字段、集合、索引和审计工具，关闭正式发布。
3. 独立重建学习成就，不清零已有合法学习成果。
4. 审核历史比赛并建立不可变事实快照。
5. 从统一初始先验开始，回放**全部审核通过的历史比赛**，不是最后 10 场。
6. 每场使用当时前缀的赛前能力构造可用难度观测。
7. 生成新题目难度、用户 Rating 和综合榜的影子投影。
8. 对比新旧差异，人工复核典型案例和极端变化。
9. 公示规则与个人明细入口，经过发布验收后切换。
10. 保留旧版榜单查询及一键回退能力。

不得从 `旧比赛分 × 4 + 1500` 之类公式恢复新能力，因为旧值可能受截断、窗口和其他政策影响。新能力只能来自经过认证的比赛回放。

### 15.4 历史不够时的启动策略

没有足够可信历史时，直接从新认证比赛开始：

- 未参赛用户的旧学习成果继续保留；比赛项显示未评级。
- 先用合格比赛建立用户本地 Rating。
- 用户达到赛前成熟门槛后，新比赛中的逐题结果才开始形成难度样本。
- 早期题目不因为之后有了成熟用户就自动补成可信难度。
- 若要给旧题建立新证据，应让真正未接触过它的合格学生在认证比赛中作答。

宁可一段时间内有很多“未标定”，也不要把日常练习包装成比赛数据。

### 15.5 跨域与全站榜

首期以 `poolId` 和授权域为边界。不同池的相同数值不保证含义相同，不能直接取最高、求平均或相加。

若多个课程域属于同一学校并确实需要统一能力榜，建议先建立共享、经过授权的共同比赛池；学习成就仍按域维护。全站复用题目的难度同样必须检查 `skillScaleId`、版本、场景和数据授权。

## 17. 效果评估：不只验证“能算出来”

### 17.1 三类指标分别评估

**数据质量**：合格观测比例、排除原因分布、无法确认时间或版本的比例、重复记录、身份异常、合格池连通情况。

**模型质量**：未来比赛名次预测、题目通过概率的 Brier 分数与对数损失、分数段校准、不同班级或经验段误差、极端和暂定比例、单场变动分布。

**产品质量**：学习与比赛贡献实际分布、只有学习记录用户的可解释性、定级期波动、重复刷同题是否无效、用户对分数来源的理解和申诉处理。

不能拿“排行榜看起来合理”代替模型验证，也不能拿“预测更好”证明某种综合权重必然公平。

### 17.2 时间切分与比较基线

采用按比赛时间的训练—验证切分。验证一场比赛时，只使用当时可得的赛前状态。题目模型的发布有效性，应在后续独立场次或新学生上验证；不能把同一题同一学生的重复结果随机分到训练与测试两边。

基线至少包含：

- 常量能力或上一状态的简单基线。
- 现有 CF 风格算法在同一合格数据集上的离线结果。
- 仅用历史合格比赛、带平滑的题目通过率基线。

所有基线都使用相同的数据资格边界，不能让新模型用干净数据、旧模型用混杂数据，再把提升全部归功于算法。

**对现有影子证据的补充解释：**`shadow-replay.ts` 先用全部观测拟合各题 D，再将观测分半拟合/评估概率校准系数 k。这只能检验给定这些 D 时的校准层表现；另一半的结果已参与 D 拟合，不能作为整个“能力—难度”管线的独立留出。已有合成恢复测试说明在相应生成假设下有恢复能力，不能证明现实中的外站等价性或动态成长已被识别。

现有 M15 只比较逐题总体期望通过率与实际通过率，而 1PL 拟合本来就倾向于让二者接近；即使高能力者失败、低能力者通过，聚合残差也可能很小。因此“异常数为 0”不能单独证明不存在反向关系。正式验收补充分能力段、分学期、分知识领域和留出比赛的诊断，检查观察到的通过率是否随能力增加，以及新旧人群的系统性残差。

外部与动态模型新增验证协议：

1. **完整时间切分。** 映射、D、θ 的初始状态、锚点选择、k、q、时间权重策略和停止规则均只用训练/调参前缀确定；最后的测试比赛不参与调参。一次前瞻预测只读取该时点可用的来源快照与模型状态。
2. **按规范来源分组。** 相同用户—题目、同场比赛和同源转载不能随机跨训练/测试泄漏；评估新题泛化时整道规范题留出。对已校准题的未来预测，允许训练中有该题，但测试必须来自独立新接触的合格学生/场次。外站公开评分若已包含同一原赛及其本地导入结果，不能把重复数据作为独立外部验证。
3. **明确前瞻与回溯。** 用当前外站快照分析过去的数据只报回溯结果；严格前瞻评估从已有可信快照的时间点开始。滚动验证中可在某场预测完成后按冻结算法更新状态，供下一场使用，但不能反过来改本场预测或选择参数。
4. **比较有用的基线。** 同时报告现有 CF 名次模型、仅使用映射后外部难度的静态模型、冻结锚点的动态顺序模型；联合迭代和时间衰减作为额外候选，只在改善独立预测时采用。
5. **评估成长与稳健性。** 除未来 log-loss、Brier、分段校准外，仿真覆盖共同成长、不同成长速度、评分滞后、熟题和场景变更；报告轨迹恢复、锚题漂移、不同年级误差及低样本不确定性。对用户/比赛作聚类重采样，并在可行时重估完整训练管线；映射误差与锚点选择另做敏感性分析，不把条件 SE 冒充全部误差。

数值上的收敛容差、候选 q、先验宽度、锚点覆盖下限和“允许多少性能劣化”的标准，应在看测试结果前登记；样本不足以判断时继续影子运行。不能用同一训练集的更好拟合来支持上线。

### 17.3 上线门槛

硬性门槛：隔离、时间、幂等、重测、权限和总分一致性测试全部通过。

模型门槛：在有足够数据的留出集上，至少不出现系统性的方向错误和明显失准；与简单基线比较有支持继续发布的证据。具体指标阈值在拿到真实基线后固定，不预先编造“准确率达到 95%”。

如果可靠留出集不足，保持“试运行／暂定”标签，不宣传评分已经精准。Rating 池尚未达到公开连接门槛时，计算结果只用于影子检查，不以正式综合比赛贡献发布。

## 18. 实施阶段与交付顺序

以下按验收依赖安排，不给没有团队规模和数据盘点依据的工期承诺。各阶段通过退出条件后再进入下一阶段。

| 阶段 | 主要工作 | 交付物 | 退出条件 |
|---|---|---|---|
| P0：规则与数据盘点 | 确认资格、题目去重、池范围、旧数据证据；盘点入口与调用点 | 决策记录、字段字典、历史候选报告、测试样例 | 作业/课程与真实比赛边界能由代码明确判断 |
| P1：可信事实层 | 原始时间与来源写入、政策冻结、赛内 journal 适配、不可变快照 | 资格服务、事实快照、排除原因管理页 | E 类测试通过，历史事实可重建 |
| P2：用户比赛能力 | 新纯算法、内部状态、公开映射、定级、池和检查点 | Rating 引擎、模拟报告、能力历史查询 | M01–M10 及相关性质测试通过 |
| P3：题目难度 | 成熟度筛选、去重、1PL、证据状态、场景版本 | 难度 Worker、诊断报告、题目投影 | 无日常数据污染，缺少证据时保持未标定 |
| P4：学习成就与综合规则 | 成就账本、部分分、P/C/RP、旧扩展隔离 | 成就明细、公式单测、对比榜 | A、C 类测试通过，算例可复现 |
| P5：发布与回放 | 串行队列、代际发布、重测回放、权限和回退 | 发布工具、运维说明、失败演练报告 | R 类测试通过；失败不污染公开榜 |
| P6：影子运行与正式切换 | 历史审核回放、真实基线评估、界面说明、灰度 | 影子差异报告、批准记录、新版榜单 | 数据、模型、产品三类验收通过 |

P3 与 P4 在 P1 完成后可以部分并行开发；P3 的正式估计仍依赖 P2 的赛前能力。界面原型可以提前开展，但不能绕开 P5 直接写生产分数。

### 18.1 角色职责

- **教学／产品负责人**：确认比赛认证标准、部分分奖励、600:400 的取向和公开解释。
- **后端负责人**：资格、事实、计算、迁移、幂等、回放与权限。
- **前端负责人**：分项单位、定级状态、缺失值、版本和个人明细。
- **数据评审／测试负责人**：历史证据审查、数学性质、时间切分评估和极端案例。
- **运维负责人**：任务监控、检查点、备份、公开指针和回退演练。

角色可以由同一人兼任，但认证、异常处置和发布决策应留下独立记录。

## 19. 风险、取舍与应对

| 风险或取舍 | 影响 | 首期应对 |
|---|---|---|
| 可靠比赛少 | 大量用户或题目暂时没有分数 | 保留学习成就；接受未评级、未标定，不借用日常数据 |
| 只有一个小班 | 本地分数缺乏外部锚定 | 明确本地相对尺度；建立共同认证比赛池 |
| 新人很多 | 初始先验可能影响老用户 | 暂定期、单场变动控制、影子比较；持续观察新人比例影响 |
| 熟题或题目重复 | 能力和难度偏高/偏低 | 规范题目来源、赛前经历排除、同人同题去重 |
| 比赛条件不一致 | 同题难度不可比 | context 分组；不默认跨时长和规则合并 |
| 先验掩盖小样本 | 看似稳定但证据薄弱 | 不把先验均值当结果，公开样本状态 |
| 日常刷题只拼数量 | 成就榜不等于能力榜 | 原始成就与比赛榜分开；成就不用于能力推断 |
| 初始综合权重不合适 | 排名偏向某类用户 | 用影子算例和实际贡献分布评审，按版本调整 |
| 重测引起历史大变动 | 用户困惑、任务量大 | 依赖回放、变更原因、完整代际切换 |
| 旧插件继续加分 | 两项总分不可信 | 新榜固定分项注册表，旧贡献另行展示 |
| 私密考试参与公共评分 | 从分数推测隐藏成绩 | 按发布前缀和授权范围隔离 |
| 管理员临时改 Rated 政策 | 选择性操纵评分 | 开赛前冻结，取消和修订均需原因及审计 |

对小号、合谋和代做，评分公式本身不提供充分防护。校内账号认证、赛事组织规则、审核和申诉仍是必要基础。

## 21. 上线批准前的最后检查

以下条件全部满足后，才适合从影子计算切换为正式榜：

- 每一个参与能力与难度更新的结果，都能追溯到认证比赛、正式身份、原始赛内提交和最终判定。
- 作业、课程、普通练习、补题、自测无论记录量如何变化，都不会污染新模型。
- 新难度不会写入旧 `difficulty`，也不会改变学习奖励。
- 学习成就、公开 Rating、能力等级、综合 RP 的含义和单位均能独立解释。
- 没有可靠数据时保持未评级或未标定，而不是自动填 0、1500 或任意极值。
- 从头重算、检查点回放和重复执行结果一致。
- 任何单场修订都能正确更新其后依赖，不能只减历史 delta。
- 任何发布失败都不会暴露半份新结果。
- 新旧规则差异有可查看的明细，私密信息不会因分数更新泄露。
- 600:400、部分分 0.5、新人 5 场和难度样本门槛已被明确批准，而非被误认为用户已经确认或平台官方标准。
- 如果采用外部锚定模型：源身份、可用时间、场景兼容性、锚点覆盖、完整时间留出均通过；文案区分外站原值、本地估计和官方用户 Rating；新能力模型对应的公开映射与 RP 政策另行批准。
- 同步失败、锚点变化或重新拟合不会直接改动当前公开代际；回退能恢复来源快照、映射、能力轨迹、难度和综合投影的同一版本组合。

## 22. 结论

建议将本项目定义为“可信比赛评价与学习成就分离改造”，而不是“RP 公式微调”。

最小可持续闭环是：

```text
明确的比赛资格
    -> 不可变的赛内事实
    -> 本地用户 Rating
    -> 有证据状态的题目难度
    -> 独立学习成就
    -> 可解释的综合排名
    -> 可修订、可回放、可回退
```

优先保证日常学习数据永不污染能力和难度，保证新旧字段不混用，保证每个分数可解释和可复算。模型复杂度和更多赛制可以后续演进，但这些边界应当从第一版就固定下来。
