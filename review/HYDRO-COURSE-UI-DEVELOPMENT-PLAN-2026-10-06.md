# Hydro 课程界面与本地反馈开发计划

日期：2026-10-06。开发分支为 `work/hydro-local-feedback-20261005`，继续更新现有 Draft PR #11。开发顺序为兼容性验证、数据契约、读取接口、A 与复测闭环、B、课程内容与管理、完整联调。各批次通过相应验收后再进入依赖它的批次。

## 已确定的业务口径

同一道题在多个课时复用时，共享“本课程该题”的提交与判题结果。课时是教师观察的上下文，不额外生成一份课时提交、重复完成次数或独立得分。课程总分、罚分、排名与既有访问规则继续使用原有口径。

页面保留 Hydro 原生布局与 A+B：A 用于沿名单连续记录，B 用于查看成绩时原位记录。课程内容复用节点、讲义和题目；课程反馈承载教师观察；待复测是反馈的待办视图；课程管理继续管理原有参与状态、排名、临时学生和访问设置。

反馈的认证、授权、录入、查询、撤销、复测处理和纠错全部由 Hydro 本地完成。备注、细项、提交编号均可空；未认领和未提交学生可在 A 记录。Accepted 不自动完成待复测，“核对过”不生成掌握度。

## D0 先确认兼容性和最小修改范围

当前工作树存在前一轮正式 UI 改动及静态原型。开始开发时先逐文件核对差异：保留本设计需要的实现，清理本轮已废弃的呈现方式，保留无关文件与用户改动。既有测试结果只作为原方案的基线，新增用例须重新执行。

建立包含以下情况的隔离课程：两个课时使用不同题目、两个课时复用同题、已有讲义和先修关系、部分学生手工访问设置、已产生提交与观察。比较重排前后的课时身份、讲义内容、访问结果、成绩、先修条件及反馈归属。

课时稳定标识优先采用现有数字 `_id`：移动课时只改变 `dag` 数组中的展示顺序，界面序号单独计算。这样继续复用现有 `nodeId`、讲义、访问设置和路由引用，减少一层 UUID 映射。新增节点需要服务端维护的编号高水位，不能按“当前最大编号加一”复用刚删除的节点身份。

兼容性用例已确定继续使用现有数字编号。现有同题成绩归属取最后一个节点，做题权限取第一个节点：分别用 `problemNodeIds` 和 `problemAccessNodeIds` 保留这两个既有规则，不随显示顺序改变。课时身份仍只有一套 `_id`，不引入 `lessonKey`。只调整展示顺序时保持原有成绩、访问和先修结果。

D0 交付：失败可复现的用例、引用清单、确定后的身份契约，以及对当前未提交实现的保留和替换清单。

## D1 稳定课时与历史兼容

按 D0 确定的身份契约实施以下任务：

1. 调整课程编辑器的重排、新增、删除和显示序号；后端验证课时身份唯一且有效，拒绝把新课时冒充已删除课时。
2. 检查课程模板、班级课程复制与同步路径。不同课程的身份以课程 ID 为范围；同一课程内的已有课时不得因复制、编辑或同步被悄悄替换。
3. 课程结构保存检查其版本，拒绝过期编辑页面覆盖更新后的结构。编辑器根据服务端返回的历史高水位提出新编号；服务端重新核验高水位，并以结构版本条件原子保存编号与结构，避免两位编辑者覆盖同一身份。
4. 新观察使用新版事件契约，服务端记录课程标题、课时标题、题目标题及课时身份。客户端只提交目标和观察，不提交可信名称快照。
5. 重试校验基于原始操作内容，名称快照不进入客户端操作哈希；课程改名不能使同一请求编号被误判为另一项操作。

旧课程的编号高水位初始化取现存结构及可查历史引用的最大值。提供只读检查和显式执行入口；实际数据修改留到获准部署时，开发期间仅在隔离数据执行。

旧观察保持原文和原始字段。缺少录入时快照、且不能证明课时归属的记录，显示“历史课时编号，名称未核实”，仍可在课程历史和待复测中查看处理；不自动拼接当前同编号课时标题，不伪造历史映射。新版按课时查看的最近观察只纳入归属可靠的记录。

主要落点：课程 `DagNode` 与编辑处理、`course_edit.page.ts`、课程复制和同步逻辑、`classroomFeedback.ts`、`classroomFeedbackAccess.ts`、反馈历史呈现。原有作业反馈不需要课时字段，继续保持兼容。

## D2 复测状态与操作一致性

每条观察独立管理状态，不按学生或题目合并待办。允许同一学生在不同时间产生多条真实“需复测”。

| 当前状态 | 操作 | 下一状态 | 权限和限制 |
| --- | --- | --- | --- |
| 待跟进 | 完成跟进 | 已跟进 | 当前课程授权教师；备注和关联提交可空 |
| 已跟进 | 撤销这次处理 | 待跟进 | 该次有效处理人或有管理权限者；必须指向该次处理 |
| 待跟进或已跟进 | 撤销原观察 | 已撤销 | 原观察教师或有管理权限者；原事实与处理历史均保留 |
| 已撤销 | 完成跟进或撤销处理 | 不改变 | 拒绝新的状态转换 |

已跟进后再次真正需要复测，新增一条观察。误点完成后使用撤销处理，两种情况在界面与数据中分别表达。

优先在现有事件集合中按观察追加带版本的变更：同一观察、同一版本只允许一条变更，由唯一索引仲裁并发；事件包含操作、引用对象和变更后的状态。服务器读取当前版本、验证状态和权限后追加下一版本，版本冲突返回当前有效状态。此方案不要求新增队列，也不以 MongoDB 多文档事务为前提。

同一请求编号仍按现有规则重放原回执，且每次重新授权。请求已经成功时，不因当前状态发生后续变化重新执行命令。不同教师的竞争请求不能返回“我已完成”的假成功，应说明已由谁处理，或提示状态已变化。

旧变更保留为历史事实。读取时按确定规则推导版本 0 的有效状态，不写入合成的初始化事件：撤销优先，已有处理按现有有效状态解释，多条旧处理均保留在详情。第一次新版转换追加版本 1，由版本唯一约束仲裁并发；所有新转换均走此路径。

待复测读取统一使用有效状态，移除现有“关联变更条数等于零”的判断。详情展示完整变更历史，不再按事件类型仅保留最后一项。撤销处理的 API 明确引用处理事件，不能复用撤销原观察接口。

主要落点：`classroomFeedback.ts`、`model/classroomFeedback.ts`、`handler/classroom-feedback.ts`、数据库索引、接口与并发测试。

## D3 本地读取契约

保留现有课程和作业反馈路由；以读取视图区分用途，共享授权及业务服务。命名在实现时与仓库风格一致，以下为需要稳定的语义。

| 视图 | 输入范围 | 返回内容 |
| --- | --- | --- |
| 名单录入 | 当前课程、课时、题目 | 当前完整学生名单、各学生最近有效观察、允许的操作、当前课程待复测总数 |
| 历史 | 课程、可选学生或题目或可靠课时、游标 | 观察分页、当前有效状态、下一页游标 |
| 待复测 | 课程、可选学生或题目或课时、游标 | 有效待办分页、筛选结果总数、本课程总数 |
| 观察详情 | 本课程观察 ID | 原始上下文、完整变更历史、当前操作能力、允许展示的提交摘要 |

名单最近观察在数据库中按学生汇总，不使用历史第一页，也不逐学生请求。撤销最新观察后可回退到上一条有效观察；“无观察”和“查询失败”分别返回和显示。

待复测总数包含本课程仍待处理的历史观察；学生已离开当前名单时标明其历史身份状态，不能因此丢失待办。A 仍只提供当前名单的新录入。删除的课时或题目使用历史上下文展示，不要求重建课程内容才能处理待办。

课程级总数不随页面筛选改变，筛选结果数量另行显示。分页游标与查询范围绑定，改变筛选后从第一页开始。当前提交、记录时提交、跟进时提交分别返回，不能用后来出现的提交覆盖原关联。

按真实查询添加课时汇总及状态版本所需索引；用隔离数据测量一次名单汇总、深页查询和精确计数，记录数据规模、执行计划和延迟，再判断是否需要额外投影。

## D4 A 名单和待复测接入

名单保持已认可的表格布局。默认选一次课时和题目后，每名学生一次点击保存“指导过”“核对过”或“需复测”；详细输入按需展开。无须签到、开始授课、逐人标记掌握度或补齐全班观察。

建立页面内共享的录入状态，按域、课程、课时、题目、学生和当前教师隔离草稿。收起、切换题目或查看历史不无提示丢弃备注；成功后只清理对应草稿并更新对应行及计数，不重排名单。

动作与细项绑定：选择其他动作时明确处理不匹配细项，不能静默丢弃后假装完整保存。成功回执显示学生、题目、动作和对应撤销入口。

待复测默认一键完成跟进，回执可撤销这次处理；需要了解背景时才打开详情。详情保留原观察、处理记录和三个不同含义的提交摘要，代码链接遵守原有源代码权限。

保存状态分为正在保存、已保存、状态待确认和明确拒绝。发请求前固定请求编号与内容，未知结果只能重试原操作；已确认保存后的列表刷新失败不得重新创建观察。关闭整个页面时对未保存草稿和待确认操作进行提示；第一版不把学生备注长期存入浏览器，也不建立离线自动提交机制。

主要落点：共享反馈组件、`classroom_feedback.page.tsx`、反馈模板及原生样式、页面与浏览器测试。沿用已有同源请求、会话与服务端权限校验。

## D5 B 进度格内接入

只在授权教师的课程成绩表启用 B。入口以服务端返回的当前学生操作能力为准；教师自己的成绩行、非名单行和公开成绩导出不提供反馈数据或操作。A 与 B 不必显示相同人数，也不自动代认领学生。

一张表同时只展开一个录入区。对象由学生与题目格预填，课时从当前视图取得；全课程视图中同题对应多个课时而无法确定时，先要求选择课时，不能猜测。

将学生主行与展开区作为一组处理名单筛选；PJAX 刷新前后保留录入对象、草稿和待确认操作。异步回复必须匹配原对象；目标已移出名单时说明情况，不将草稿交给相邻行。组件重挂载不得重新发出写入。

使用同一个反馈控制逻辑，避免每个成绩格各挂载一套完整名单组件。只对课程启用相关生命周期处理，普通比赛和作业共享成绩表继续按原逻辑运行。

成绩显示继续使用已有真实分数、提交次数、时间和排名数据。按课时显示同题时标注共享本课程结果；不显示独立完成次数，不把颜色判断用的 100/0 当真实分数。

主要落点：课程成绩处理器、`partials/scoreboard.html`、`contest_scoreboard.page.ts`、共享录入状态、刷新与筛选浏览器测试。

## D6 内容与管理页面收口

课程内容按现有课时结构展示讲义和练习；保留原有题目页、讲义页和编辑器。第一版不新增章级管理、IDE 或课时提交系统。课程反馈、待复测、管理导航由服务端按各自权限提供；域开关关闭时恢复原有入口。

管理区保留班级成员、临时学生和节点设置三类业务。讲义是否有内容与学生是否可访问分别展示，当前可访问人数标明分母和名单范围。统一开放、关闭、恢复规则属于动作，不能用一个全局“已开放”概括所有学生。

批量排名沿用当前全课程作用范围，并在确认页明确对象；班级代认领等操作保持各自原范围。确认页显示实际动作、课时或题目、名单和人数，不使用泛化的“确定执行吗”。

批量操作按实际对象返回成功和失败结果，失败项可以单独重试。现有逐节点调用可继续复用，但每项结果须被收集，避免一次调用一次全页刷新。后端若在一次节点操作中处理多名学生，也要报告其中的部分失败，不能只靠前端汇总掩盖它。重置仍只恢复访问设置，提交、成绩、观察和处理历史保留。

## D7 验证与交付

验收采用评审报告的 15 项用例，并在各批次补充下列重点：

- D1：删除最高编号课时后新增不复用；复制和同步不替换已有课时身份；两位编辑者或过期页面不能覆盖新结构；仅移动展示顺序不改变已有成绩与先修结果。
- D2：并发完成、并发撤销、完成与撤销竞争、撤销处理后再完成；回执丢失后原请求重试；旧处理历史初始化及不同请求编号的竞争。
- D3：超过一页的最近观察回退、深页待办、筛选计数、名单移出和题目删除后的历史处理；作业反馈兼容。
- D4 与 D5：连续快速点击、回执与加载先后变化、成绩自动刷新、名单筛选、换格、收起、权限变化、整页离开；桌面与窄屏键盘操作。
- D6：混合开放状态、批量部分失败、仅重试失败项，以及普通课程编辑、成绩导出和非课程成绩表回归。

先执行相关单元、真实 MongoDB 与 HTTP 测试，再执行默认 UI 浏览器验证和项目要求的构建、测试、lint。既有工程失败与新增失败分别取证；不能用原型检查代替默认界面联调，也不能把历史通过数字当作新版结果。

本地验证以 WSL `Ubuntu-22.04`、Docker `hydro` 的实际依赖环境为依据，使用隔离进程或临时验证环境及测试数据库。查询运行版本和健康状态可以只读进行；本轮不替换运行中的包、不重启服务、不连接真实课程数据执行测试。

交付更新后的源码、索引与兼容脚本、自动化测试、界面验证证据、开发状态及验收结果，提交到既有分支并更新 Draft PR #11。不得合并、发布或部署。真实班级试点与运行环境安装升级留到另行授权部署之后。

按用户 2026-10-06 决定，移除本轮“材料可得条件”任务，不增加教师配置或录入步骤。模拟集训另行设计；AI-EDU 消费端和线上 IDE 轨迹不属于本轮。
