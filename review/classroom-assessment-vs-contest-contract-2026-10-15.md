# 课堂测试与普通比赛：边界、权限和数据契约（2026-10-15）

适用：Hydromod `course-v2.2`，PR #27。课堂测试是课程的限时测评业务类型（`sourceType='course_assessment'`），**不是**额外的判题赛制。复用 `oi/ioi/strictioi/acm` 的计分引擎，但父课程是人员、章节和管理权限的唯一事实来源。

## 1. 对照表

| 主题 | 普通比赛 | 课堂测试（强制契约） |
| --- | --- | --- |
| 对象归属 | 独立比赛 | 绑定单一 `sourceCourseTid + sourceNodeId`，唯一关联父课程 DAG；绑定不得自行变更 |
| 题目、赛制、时间 | 比赛编辑器 | 父课程章节编辑器；子比赛只接受课程同步；已开始的题目/赛制不可变 |
| 名单来源 | 比赛 `assign` / 报名 / 管理员添加 | **父课程**的在册班级学生和 `extraStudents`；班级教师与课程 owner/maintainer 为教师，不得另建独立名单 |
| 资格 vs 实际到场 | 报名记录决定参赛资格 | 父课程名册+本人已进入课程+节点解锁决定**资格**；本人在测试有效时间内开始测试才产生子比赛**到场记录**；不得因为在班级名单里就虚构出席 |
| 报名管理 | 比赛管理独立增删参赛者 | 禁止独立增删、取消及改排名/恢复参赛者；课程名单和章节权限统一在课程管理中修改 |
| 学生入口 | 比赛详情与报名 | 课程章节的「进入课堂测试」；测试期内可以开始测试；不用为某场测试另建名单，也不开放课程外自主报名 |
| 教师权限 | `PERM_EDIT_CONTEST` / 比赛维护人 | `PERM_EDIT_HOMEWORK` 或课程 owner/maintainer + `PERM_EDIT_HOMEWORK_SELF`；权限检查应读取父课程，避免误用独立比赛管理员身份 |
| 题目访问 | 比赛开始、本人到场及题目权限 | 教师可提前预览；学生必须具有课程资格，正式窗口内需实际开始测试；赛后符合规则可以练习。普通比赛流程不变 |
| 提交结果 | 比赛正式记录 | 时限内学生正式记录 `contest`；教师提交为 staff，绝不视为学生测评；赛后练习为 `practiceContest` |
| 赛后补交 | 比赛显式开启 | **默认开启**（历史值缺失也开），明确设为 false 才关闭；无需补报正式参赛；有父课程权限且节点解锁者可练习 |
| 结果与达标 | 正式比赛成绩 | 独立测评正式日志计算分数、结束后出结果并推动课程章节解锁；赛后练习不影响原成绩与达标 |
| Rating | 合格且认证的真实限时比赛 | 仅**赛前认证**、明确真实出席和有效时间戳、正式学生提交、冻结参与名单与原题版本才可统计；教师和练习均排除 |
| 监控 | 比赛监控开关 | 仅正式考试期间，教师按课程权限查看；练习不自动被视为监考考试 |
| 成绩、代码、答疑 | 比赛管理员管理 | 教师按父课程权限查看成绩/代码/监考/答疑；学生不应借比赛管理员权限看到全班隐私信息 |
| 课程变动 | 无父级同步 | 班级/临时名单、维护人、章节和时间变化通过父课程同步/实时授权生效；访问撤销阻止新提交/查看，但不删除历史原始成绩 |
| 独立页面 | 比赛管理、参赛者管理、编辑比赛 | 隐藏或拒绝独立编辑及参赛者**写操作**；只保留必要的课堂教师只读数据入口，并跳转回父课程管理 |

## 2. 三种状态不得混淆

1. **课程在册**：是否属于有效班级学生或课程临时学生（父课程 `assign`），与课程管理中新增/移除同步。无班级/临时名单不得通过一个公开子比赛报名 URL 自行获得参赛资格。
2. **课程章节已开放**：课程本人已有 `attend` 且 `status.allow[nodeId] === true`；教师用统一课程管理权限绕过学生节点限制。取消节点授权后，新的题目访问、补交及其记录订阅全部被拒绝。
3. **限时测试实际到场**：已经有测试自身 `tsdoc.attend`，仅代表此人在测试有效期间开始参与。未在限时内参加的人，测试结束后仍可补提交，但不得生成测试到场/测试正式分数，也不能进入能力 Rating。课程学生名单与实际测试出席名单不同。

## 3. 安全与一致性不变量

- 授权应检查**当前父课程**是否真实存在、是否是正常课程、节点是否仍绑定对应测试，以及用户当前是否属于课程名册并具备节点权限。子比赛副本 `assign/maintainer` 只是同步信息，不能作为豁免父课程的依据。
- 普通比赛原有 `PERM_VIEW_CONTEST_SCOREBOARD`、`PERM_EDIT_CONTEST`、`allowPractice` 与报名流程不变；课堂测试专有读取及管理入口应由父课程权限控制。
- 任何课堂测试管理端点不能允许教师人工添加无父课程资格的子比赛参赛者、直接改班级名单、直接修改独立比赛时间/题目/Rating 或绕过课程章节限制。
- 教师可以查看题目（含赛前），但不能因为预览而自动生成学生正式出席或考试成绩；限时窗口外不得产生新的**正式**测评提交。
- 班级调整、临时名单调整、课程撤销、节点封闭后不抹除已发生的正式测评记录；从此刻起必须阻止无权限继续访问和提交。
- 已通过测评的后续课程达标计算严格使用子比赛正式参赛日志，排除练习 `practiceContest`。评级使用额外赛前冻结证明，不能拿普通课程日常练习计算。

## 4. 本 PR 需要修复、验证的代码边界

1. `ContestProblemListHandler`、`ProblemDetailHandler._prepare`、`ProblemSubmitHandler.prepare/post`：防止教师可管理但被普通比赛「未到场」拦住；保证学生赛前/赛中/赛后分别遵循独立规则。
2. `ContestUserHandler` 的所有写操作：课堂测试禁止子比赛单独添加、删除、unrank 和 resume；可用父课程入口查看与管理学生，子比赛实际到场只由合格学生开始测试产生。
3. 课堂成绩路由、默认实时分数、代码导出、练习记录：教师以父课程权限进入，不要求额外比赛管理员/比赛成绩权限；普通比赛保留既有规则。
4. `assertCourseAssessmentAccess`：真正依赖父课程的 owner/maintainer + SELF 或全局课程编辑；无名单自助入课不构成课堂测试参赛资格。
5. 对学生参加正式测试、教师赛前预览、独立参赛者写入口、默认补交、权限撤销、Rating 与课程成绩隔离做回归测试。

## 5. 本次不做

- 不把「没有实际参加测试的人」自动登记为参赛者，不批量生成子比赛到场状态。
- 不改变「我的课程」的现有归类规则；学生不能自行加入普通课程，此处不扩展开放课程语义。
- 不新增 `rule='classroom'` 或复制 OI/IOI 判题、评分引擎；`sourceType` 承载业务类型，`rule` 仅承载赛制。
- 不因 GitHub Actions 配额不足推断代码构建失败，也不擅自合并或发布。
