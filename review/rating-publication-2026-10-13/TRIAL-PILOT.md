# Hydro Rating V2：限域真实试用与验收计划（2026-10-13）

## 目的与原则

允许系统管理员仅在明确选中的少数域，使用**真实历史数据及后续新增数据**试用评分；不因为历史未具备 certified 证据，就禁止探索数据价值。试用结果应清楚标示为试用，不能宣传成已验证的独立竞赛能力。原始 RP 不迁移或擦写。

系统有两条彼此独立的评分链路，不应将不同目标的数值混为一个正式 Rating：

| 来源 | V2 公开奖励试用（P+C） | 练习 R/D 只读试用 |
| --- | --- | --- |
| 已结束、可公开、rated=true 的比赛 | 参与比赛/测试 Rating（C）；有效做题成果可计入 A（P） | 依既有练习数据提取规则 |
| 真实课程关联的课堂测试 | **本轮新增**，需课程/节点关联一致、考试结束、成绩可展示，且学生已报名、不是课程教师；只在 V2 试用域参加 C | 依现有练习数据提取规则，不自动取得认证身份 |
| 普通课程、作业、练习的做题记录 | 合法可见的最高结果可计入成就 A（P），**不作为独立比赛名次**，不直接更新 C | 正常学习提交用于独立 1PL 练习 R/D（7 天完成概率，管理员专用） |
| 赛后个人练习、虚拟参与、非正常提交 | 不计入限时赛事 Rating 的有效比赛记录 | 按既有练习模型准入，不把练习当作正式参赛 |

- V2 **trial** 对历史 rated 比赛不要求补造赛前认证；课堂测试允许未认证但必须通过真实课程绑定、赛后公开和有效报名校验。
- **certified** 仍是更严格、独立的认证回放口径，暂不通过本发布开关取代 trial。当前少数域试用不能证明正式等级有效性。
- 公共页面注明“限域试用，非认证竞赛能力”；课程的练习 R/D 页面继续限制系统管理员访问，默认关闭，不向教师或学生解锁。
- 跨域不合并用户 Rating 或题目难度；不同域仅作域内试算。暂不增加另一套加权模型或重新定义 600P+400C。

## 启动一个真实试用域

1. 先审核目标域的题目和可公开成绩规则，优先挑选学习活动真实、人数有代表性的 1–2 个域；不要在所有域批量开启。检查原 RP、公开榜、域成员和隐私设置。
2. 系统管理员进入 `/manage/rating`，选择 **V2 试用版**，明确填写目标域 ID；点击“保存目标设置”。**仅保存不会改变公开分数。**
3. 为目标域执行一次“重算并应用”。等待该次运行完成，检查活动批次编号、处理场次、rated 场次与课堂测试场次、学生总数、原 RP 对照和结果可见性。若重算失败，原公开分数保留。
4. 核对含真实课堂测试、普通课程做题和比赛历史的学生样本：A 是否反映公开学习成就；C 是否只来源于合格的比赛/测试成绩；无比赛记录的学生必须显示“未评级”，而不是把 A 当 Rating。
5. 检查班级教师、普通学生访问课程练习 R/D 页面仍为 403，确认仅管理员试用。验证退域、重新加入、隐藏用户和并列分数的排名。
6. 试用域的**每日一次 RP 任务**仍按当前已发布的算法更新；管理员更改目标域名单不会立即切换已生效批次。需明确执行回退或切旧版重算才恢复。
7. 若需要恢复，使用该域“恢复上一次评分”，并核对 `runId`；不要把回滚与另一次不同截止时间的旧算法重算误认为相同结果。

> **发布前提：** 仓库 `AGENTS.md` 要求每次私有 npm 发布单独获得用户授权。本 PR 只改源码、测试和说明，不发布或升级本地/线上容器。首次真实部署后必须验证包的实际版本及 `/manage/rating` 页面，不能仅信赖安装脚本退出码。私有 registry 不可用时暂停，而非更换源或复制包。

## 普通学习数据 R/D 的同步试用

这条独立链路已经在当前分支具备开关和未来验证工具，不需要重写一套模型：

1. 对选定域运行管理员脚本 `practice-rating-configure`，按需设置 `enabled=true`（参加每日影子计算）、`adminTrial=true`（管理员可访问课程只读 R/D 页面）。两项开关互不替代，不会自动启用 V2 公开排名。
2. 用 `practice-rating-run`（先 `write=false`）检查数据容量、样本充足度与排除数量，再启用每日影子写入；`practice-rating-report` 可检查指定学生/题目数据，不修改公开评分。
3. 选取未来实际要布置的学生-题目配对，在首次尝试前用 `practice-rating-freeze` 固定预测，并记录返回的 `predictionId`。
4. 待对应 7 天结果成熟后用 `practice-rating-evaluate` 计算真实预测质量；不要在冻结后重新拟合过去的数据再把训练拟合当作未来成绩。
5. 教师和学生仍不能进入 R/D 私有试用页面；`enabled/adminTrial` 只对指定域设置。需要停止时分别关闭开关。

## 质量验证（以真实试用积累证据）

- 冻结未来一批真实学习过程及学生/题目配对的试用预测，经过完整 7 天窗口再统计覆盖率、分桶校准与 Brier（对比相同可评分样本上的简单总体完成率），不能用训练内拟合对账冒充未来预测。
- 分别统计 rated 真实比赛与课程课堂测试的场次、有效人数、排除原因、能力历史场次数；课堂测试作为真实教学测评，但不能自动推断为防外部辅助的认证比赛。
- `cppbasics`、`cspjs` 优先观察样本外预测，并记录 `cpptrain` 超量以及历史题目版本未知造成的覆盖缺口；不因第一轮分数不足就自动放宽正式准入门槛。
- 等到足够未来重复参赛、课堂测试和未来练习样本累积后，再决定是否扩大到更多域或开放其他用户角色。当前不要将练习 R/D 直接加进公开比赛 C。

## 本轮回归范围

- 显式开启课堂测试纳入 trial；保持独立运行 `runShadowReplay` 的默认行为不变，避免历史影子分析任务的口径被悄然扩大。
- 拒绝伪造的课堂测试 sourceType、课程/节点变更、未公开成绩、未报名的学生，以及显式个人练习/非正常提交。
- 当前在域/可见用户的排行榜名次实时重新确定（含并列），不影响已保存的历史分数快照。
- 安装器遇到远端 dev 版本未知时返回非零状态；选择的版本必须与实际包版本相符，不能把安装脚本成功退出误认为实际升级。
- 使用 `npm test` 的新测试以及 `npm run test:rating-publication`；GitHub Actions 额度问题不作为代码回归通过证据。真实浏览器和真实域试用需在得到明确发布授权后执行。

## 不在本次 PR 的范围

- 不新增比赛即时批量重算的并发框架。用户已确定维持既有每日一次评分机制；赛事成绩修正仍走现有独立流程。
- 不改练习 R/D 数学公式、不开放教师学生权限、不切换所有域、不替换严格 `certified` 的未来赛前冻结要求。
- 不发布、不部署、不操作真实账号数据；生产成绩的预测有效性尚待试用测量。
