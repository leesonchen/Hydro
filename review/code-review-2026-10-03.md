## 新增代码问题

### 1. P1：普通用户可以通过域设置请求使未验证角色生效

位置：`packages/hydrooj/src/model/domain.ts:425`、`:454`、`:539`；关联既有入口 `packages/hydrooj/src/handler/home.ts:503`。

新流程先将邀请角色写入 `domain.user.role`，用 `_roleAssignment` 标记限制实际权限；`getDomainUser` 仅在标记为真且角色相匹配时使用原角色。域设置入口的 `booleanKeys` 没有设置项白名单，可以把用户自己的任意域字段写为 `false`。

已用真实 HTTP 接口复现：

1. 创建普通用户和两个自定义角色，邀请角色额外拥有 `PERM_EDIT_DOMAIN`，用户原角色没有该权限。
2. 在真实 `joinUserInDomain` 执行中注入角色复查失败及回滚写入失败，生成未验证状态。这也是仓库现有测试已经覆盖的故障类型。
3. 确认用户实际角色仍为原角色。
4. 用户向 `/d/<domainId>/home/settings/domain` 提交 `{"booleanKeys":{"_roleAssignment":true}}`，接口返回 302。
5. 重新读取真实 `UserModel.getById`：角色变为邀请角色，`hasPerm(PERM_EDIT_DOMAIN)` 为 `true`，尽管验证从未成功。

这条漏洞由新引入的角色状态与既有任意布尔字段写入入口共同产生；并非用户可以任意指定任意角色，而是可以绕过未验证邀请角色的权限限制。

建议：`booleanKeys` 只接受注册的布尔设置项；成员身份、角色及内部验证字段不得通过个人设置接口修改。补充真实 HTTP 回归，覆盖故障后及并发验证期间的标记篡改。

### 2. P2：只修改成员状态也会错误地确认待验证角色

位置：`packages/hydrooj/src/model/domain.ts:44`。

`invalidateRoleAssignment` 对 `join`、`requireInvitation` 的任何修改都会直接删除 `_roleAssignment`，却保留已经写入 `role` 的待验证角色。验证者随后按 token 完成或回滚时找不到标记，转而读取当前记录，因而不能恢复原角色。

独立模型探针已复现：已入域的 `student` 接受 `teacher` 邀请，在角色复查前调用 `setUserInDomain(..., { requireInvitation: false })`，随后令复查失败。最终角色仍是 `teacher`，预期应保留 `student`。

这与问题 1 的修复点不同：即使个人设置入口增加白名单，模型层合法的成员状态写入仍不应自动确认待验证角色。建议仅在显式、受信任的角色重设时替换待验证状态；成员状态变更应保留验证标记，或在原子更新中先恢复已验证角色再取消它。

### 3. P3：`__proto__` 角色创建返回成功但未实际创建

位置：`packages/hydrooj/src/handler/domain.ts:296`、`packages/hydrooj/src/model/domain.ts:340`。

新的 `Object.hasOwn` 检查允许 `__proto__` 通过重复角色检查，现有 `Types.Role` 也接受此名称。但是普通对象的 `updatedRoles[name] = permission.toString()` 会触发继承的原型 setter，字符串赋值被忽略。

已确认：调用真实角色创建方法完成并重定向后，角色列表没有 `__proto__`。建议明确禁止保留名称，或使用无原型字典/自有数据属性存储。本项是低优先级功能问题，不单独作为发布阻断理由。

## 后续评审修复

### P2：特殊名称角色的 HTTP 管理不完整

评审成立：模型允许持久化 `__proto__` 后，旧权限表单以角色名作为字段名，会被 `co-body` 丢弃；相同 JSON 字段会被解析器拒绝。成员列表的普通对象字典还会触发继承的原型 setter。进一步真实 HTTP 检查发现，框架序列化器会过滤以 `_` 开头的字典键，所以只改为无原型字典仍不足以修复 JSON 响应。

最终修复：

- 新角色在模型与创建处理器中拒绝 `Object.prototype` 的自有名称，包括 `__proto__`、`constructor`、`toString`。已有同名角色继续支持权限修改、分配、默认设置、排序及删除，不做数据迁移。
- 权限表单使用编号条目，以字段值传递角色名。新增 `operation=update` 的结构化表单/JSON 路径；保留原有普通角色的平铺请求，并兼容超过 20 个角色时解析器生成的编号对象。
- 权限字典、成员字典和 Shift 点击状态字典使用无原型对象。权限输入拒绝重复角色及无效位索引，继续保护 root 角色并支持扩展权限位。
- 框架响应可以显式标记公开字典。只保留这些字典自身以 `_` 开头的键，成员值、域邀请配置和其他内部字段仍按原规则过滤；输入解析器的保护保持不变。

### P3：退出时仍在处理事件的竞态

退出与卸载现在共用幂等的停止流程：阻止新事件、唤醒空闲或重试等待、等待已领取的轮询事件和已启动的变化流处理器，并关闭变化流。五秒期限到达后记录警告并取消数据库查询/变化流；强制停止后返回的查询结果不会再派发事件。处理器异常会被记录，轮询继续运行。

兼容影响：退出可能等待最多五秒。超时强制停止仍可能丢失未完成事件，也不能强制取消任意正在运行的 JavaScript 处理器。真实 MongoDB 的阻塞查询和变化流取消行为已验证。
