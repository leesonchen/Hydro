# Hydro 测试监控：学生端与在线编程约束（2026-10-14）

目标分支：`course-v2.2`；实施 PR：#21。仅适用于已经参加、尚在测试时段、且 `monitorMode=browser` 的比赛/课堂测试。本轮不改非监控比赛、普通练习、AI-EDU 或 GESP。

## 一、学生可见界面

- **顶部**：将横跨页面的黄色技术性说明，替换为内容区内的紧凑浅色提示：**「测试监控中｜测试结束前，请保持全屏模式，不要切换到其他窗口或应用。」**；未全屏时提供「进入全屏」，全屏后隐藏按钮；网络异常时单独出现短暂提示。
- **离开后返回**：浏览器标签隐藏/恢复、窗口失焦/聚焦与全屏退出继续上报。回来时出现「测试监控提醒」，仅告知离开或退出全屏、约略时长，以及「本次行为已记录，供监考老师查看」。按钮「我知道了，继续测试」确认后继续；不凭监控事件自动认定作弊。
- **题目列表及侧边栏**：监控中的代码题直接提供「在线编程」入口，不再展示旧「提交文件/提交」跳转；点击从题目列表直接进入标准编辑器。侧边栏提供「基础编辑模式」备选入口。旧提交页的直接访问会重定向回在线编程；非监控页面维持旧入口。
- **文件型特殊题**：新建/编辑监控比赛或课堂测试时，后台拒绝含 `submit_answer` 的题目配置；对于已存在的旧配置，学生页面提示联系监考老师调整，不提供文件上传入口。

## 二、标准 IDE 与基础编辑模式

- **代码初始值**：监控测试不注入个人代码模板。正常练习及非监控比赛仍使用原 `codeTemplate`。
- **草稿隔离**：按账号、域、题目、比赛及参赛开始时间建立监控草稿键；避免普通练习及旧一轮测试的草稿注入。标准 IDE 和基础编辑表单通过浏览器本地草稿进行衔接，后台不新增草稿字段。对于禁用本地存储的浏览器，编辑期间仍可正常提交，但不能承诺刷新恢复。
- **标准模式**：保留 Monaco 编辑器、预评测、常规快捷键与现有设置。React 通过错误边界和编辑器就绪事件确认实际可编辑后才隐藏基础表单；Monaco 加载失败使用 React textarea，React 自身挂载失败或等待超时则恢复独立 HTML 基础表单。手动切换基础模式使用整页导航以确保草稿刷新。
- **基础模式**：直接由 Hydro HTML 页面提供 `textarea + lang + form`，即使高级编辑器模块未加载也可作答和直接提交。普通输入、基本 Tab 缩进、草稿保存不依赖 Monaco；无 JavaScript 时仍可输入/提交（客户端监控与草稿保存则无法工作）。
- **代码文件上传**：隐藏旧上传界面并在后端提交处理处阻止携带本地文件的请求（包括预评测），保证不能通过手工拼装提交绕过。

## 三、复制与粘贴

- 仅在本轮监控页面生效；从其他页面复制代码并粘贴到 IDE 会被阻止。
- IDE 内复制/剪切时，用标准文本作为剪贴板的 `text/plain` 数据，并尝试额外写入私有的 `application/x-hydro-monitored-code` 标记；代码文本自身不插入零宽字符，不要求评测服务清洗代码。
- IDE 粘贴时将文本、存在时的标记，与当前页面内最近一次合法复制记录比对。校验时对 CRLF/LF 等价换行进行规范化，防止合法的多行代码粘贴被误拒；写入 IDE 的代码保持最初复制的内容，不带标记。浏览器丢失私有标记时，只要原始文本仍匹配本页复制记录即可粘贴；没有剪贴板事件数据的旧浏览器使用内存缓冲。
- 离开页面或浏览器失焦时清空本页复制缓冲。拦截 `drop`、`beforeinput=insertFromDrop` 与来自外部的粘贴；允许正常撤销、重做、缩进和输入法。鼠标右键菜单不再被一刀切禁用，实际复制粘贴仍执行来源校验。

## 四、适用范围与后续

1. **不实施 OS 锁定**：网页只能检测部分切换信号，无法锁死其他程序、屏幕录制、开发者工具和第二台设备；监控日志不能单独作为作弊证据。
2. **不实施 AI 辅导服务改造**：PR #21 曾新增的 `packages/ai-assistant/index.ts` 修改已全部撤回。后续再独立规划 AI-EDU 和 GESP 课程的受控辅导策略。
3. **兼容性限制**：基础 HTML 表单可以在高级前端不可用时独立工作；但无 JS 时无法运行客户端监控与剪贴板拦截。旧浏览器的具体最低版本仍需实际验收。
4. **跨页剪贴板**：本轮有效复制记录只保留在当前页面实例内，跨题跳转后需要重新复制。后续可按考试会话增加跨页剪贴板缓冲，但不得放宽外部来源校验。
5. **课堂测试/普通比赛**：基于已有 `monitorMode` 设置，不改变题库、判题、分数、RP 或 Rating 逻辑。

## 五、回归验收

| 场景 | 预期 |
|---|---|
| 正常监控页面初次打开 | 顶部只显示简洁监控提醒；全屏按钮可用 |
| 切换其他窗口、切换标签再返回 | 一次明确的「测试监控提醒」，确认后继续 |
| 进入同一道题的在线编程 | 默认代码空白；本次测试中已保存草稿可恢复 |
| 进入普通练习/非监控比赛 | 原代码模板、草稿、提交入口和剪贴板保持原样 |
| Ctrl/Cmd+C、Ctrl/Cmd+V、Ctrl/Cmd+X | IDE 内成功；没有签名或匹配复制记录的外部代码不能粘贴 |
| 浏览器剪贴板不支持自定义 MIME | 内容仍匹配最近一次 IDE 复制时允许粘贴 |
| 拖入代码或文件 | 阻止注入、监控事件记录 |
| 高级 IDE 加载失败 | 基础编辑模式仍可输入、缩进、提交 |
| 访问旧提交表单或直接上传文件 | 代码题被重定向；上传请求由服务端拒绝 |
| `submit_answer` 文件型题 | 不允许文件提交；联系监考老师调整题型 |
| 同源页面导航、bfcache、网络离线 | 原有监控事件队列、去重及恢复行为保持 |

测试文件：`test/monitored-exam-restrictions.spec.js`，并已加入仓库的 `test` 脚本；原 `test/contest-assessment-monitor.spec.js` 的监听器及持久化逻辑要求保留。

## 六、正式评审修复与验证记录

- **P1 事件上报旧浏览器兼容**：无 `fetch` 时使用 XMLHttpRequest，保留 ACK 校验、持久化、断网重试逻辑；避免旧式浏览器不支持的 `Array.prototype.findIndex`。
- **P1 剪贴板误拦截**：仅在判定来源时将 CRLF/CR 换行规范化为 LF，实际粘贴内容不注入不可见字符。
- **P1 编辑器异常回退**：等待 Monaco/React textarea 就绪信号，React 错误边界与 18 秒就绪超时兜底；仅确认能编辑后才隐藏基础表单。
- **P1 文件型题目冲突**：普通比赛设置和课程中的课堂测试同步前分别做后台题型校验，阻止含 `submit_answer` 的监控配置。
- **P2 正常体验**：基础表单优先调用浏览器编辑命令维持 Tab 撤销历史，不支持时回退到 setRangeText；监考老师页面以中文展示监控事件；手动切换编辑模式时整页导航以便草稿 flush。
- 新增/更新的客户端回归测试：**18 项模拟及静态检查通过**（非 GitHub Runner 的正式 CI 执行）；课堂测试集成测试还增加了文件型题目被拒绝的用例。

**验证边界**：本环境仍无法解析私有仓库 GitHub 克隆域名，无法执行完整的 `yarn build`、`yarn lint:ci`、Nunjucks 真实渲染、MongoDB 集成测试或 Chrome/Edge 实测。GitHub Actions 最新 CI 已触发但因尚未分配 Runner、没有执行步骤即失败；目标分支近几次运行也有同类现象。此现象不能归因于 PR 代码，也不能视为正式 CI 通过。PR 保持 Draft，验收前不合并、不发布。
