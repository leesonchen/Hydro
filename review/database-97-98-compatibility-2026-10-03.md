# 数据库版本 97 与 98 的兼容性检查

检查对象：将 `course-v2.1`（`cba8aa6a`）合并到 `course-v2.2`（合并前为 `d696da7b`）后的代码。

## 结论

97、98 是 Hydro 的数据库迁移序号，不是 MongoDB 软件版本。

| 代码与数据库组合 | 结论 |
| --- | --- |
| v2.2 代码 + DB 97 | 支持自动迁移到 98；必须先通过参赛数据审计。 |
| v2.2 代码 + DB 98 | 迁移版本匹配，不需要再次执行 97→98。 |
| 原 v2.1 代码 + DB 98 | 默认拒绝完成启动；不能视为支持的回退组合。 |
| 原 v2.1 代码 + DB 98，强行跳过版本检查 | 部分个人参赛数据在结构上仍可读取，但不能保证写入约束、团队参赛及权限/计分行为兼容。 |

本轮角色管理修复没有新增数据库迁移。合并后保留 v2.2 的第 98 个迁移和团队比赛逻辑，仍预期 DB 98。

## 97→98 的实际变动

迁移入口为 [`_97_98()`](../packages/hydrooj/src/upgrade.ts)，实现为 [`migrateContestParticipantUids()`](../packages/hydrooj/src/lib/contest-participation.ts)。

1. 先只读审计所有 `docType = 30` 的比赛/课程/作业文档及其报名状态。检查重复参赛、无效或不存在的团队成员、成员字段与参赛者字段不一致、配置与团队状态矛盾、报名计数不一致等问题。任何 finding 都会阻止迁移，不会自动删除或修复冲突记录。
2. 为 `document.status` 中已报名且尚无 `participantUids` 的记录补写该字段：个人为 `[uid]`；团队为去重、排序后的 `members`。同时支持历史布尔型 `attend: true` 和数值型 `attend > 0`。不删除、重命名原字段，不改提交记录、分数、题目或角色数据。
3. 确认无待补写的有效记录，再次审计。
4. 创建 `contestParticipant` 唯一多键索引：`{ domainId: 1, docType: 1, docId: 1, participantUids: 1 }`，仅覆盖存在 `participantUids` 的记录。它保证同一域、同一场比赛中，每个用户只出现在一份参赛状态里，阻止跨团队或个人与团队重复参赛。
5. 迁移成功返回后，[迁移服务](../packages/hydrooj/src/service/migration.ts) 才将 `db.ver` 写为 98。失败不会推进版本号；补写操作只处理缺字段的记录，允许重试，但并非整个迁移的事务回滚。

新数据库初始化也创建该唯一索引。

96→97 的比赛/作业附件路径调整属于前一条迁移，不是 97→98 的差异。

## 为什么不能直接降回 97 版代码

[迁移服务](../packages/hydrooj/src/service/migration.ts) 用迁移数组长度作为代码预期版本。原 v2.1 为 97，合并后的 v2.2 为 98。

当数据库版本大于代码预期版本时，默认会停在启动流程中。因此 PM2 进程仍可能显示 `online`，HTTP 服务却尚未就绪；这与此前 hydro 容器升级到 v2.1 包后出现的现象一致。

虽然 98 的补写是新增字段，但原 v2.1 的 `contest.attend()` 不维护 `participantUids`。新增报名记录没有该字段时，不在部分唯一索引覆盖范围内，可能破坏新版的参赛者唯一约束。以后重新运行 98 版代码时，因为 `db.ver` 已是 98，也不会自动重跑补写迁移。

此外，v2.2 新增 `allowTeam`、团队虚拟用户及参赛状态的 `members`/`displayName`，并同步调整参赛查询、提交记录权限、榜单和 Rating/RP 筛选。原 v2.1 不具备这些行为。因此不能仅凭“新增字段通常可忽略”推导整个旧版本可安全读写团队数据。

## 升级前提

从 DB 97 升级时，需要先消除审计发现的异常。即使从未使用团队比赛，历史 `tdoc.attend` 与真实报名状态条数不一致，也会阻止升级。

已经是 DB 98 的安装应使用保留第 98 条迁移和相关团队逻辑的 v2.2 包。不能把 `db.ver` 改回 97 或用 `--ignore-version` 代替代码兼容性处理。

## 验证记录

在隔离的临时 MongoDB 中直接执行仓库迁移辅助函数，未连接容器数据库：

- 个人报名的布尔/数值 `attend` 和团队报名均补写正确；其他原字段逐项保持一致。
- 第二次执行更新 0 条记录。
- 创建的索引名称、键、唯一属性及部分过滤条件正确。
- 含相同成员的新团队记录被唯一索引拒绝，错误码为 11000。
- 模拟旧代码写入不含 `participantUids` 的个人报名，能够绕过部分索引；审计报告 `personal-team-duplicate`，迁移拒绝继续。
- 模拟无团队课程的报名计数不一致，审计报告 `attend-count-mismatch`，迁移拒绝继续。

合并验证还包括序列化冲突回归：公共角色字典保留 `_teacher` 等键，同时参赛状态的 `participantUids` 和内部字段仍被过滤。

完整测试暴露并修复了 v2.2 的两处现存回归：

- `contest.edit()` 的并发条件此前按普通属性读取 `lecture.1` 等 MongoDB 字段路径，导致已有讲义无法更新。现在按路径读取原值；HTTP 测试确认讲义可以更新，过期快照仍被拒绝。
- 记录详情此前允许作者/队友绕过 `canShowSelfRecord()` 的拒绝结果。现在必须通过可见性策略；HTTP 测试确认已公开的团队记录仍可读，隐藏成绩时作者/队友均返回 403，比赛管理者保留访问权限。

验证结果：98 项单元/回归测试、34 项 HTTP 集成测试通过；framework 和 hydrooj 的 TypeScript 检查通过。使用 v2.2 当前声明的依赖，TypeScript 为 6.0.3。迁移数组静态检查确认原 v2.1 预期 97，合并后的 v2.2 预期 98。包基础版本保持 framework 0.3.2、hydrooj 5.0.7、ui-default 4.58.5。
