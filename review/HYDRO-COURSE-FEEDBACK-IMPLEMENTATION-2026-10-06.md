## 数据与兼容处理

课时继续使用已有数字 `_id`，界面序号按数组顺序显示。移位不重编号，讲义、访问设置、先修关系和历史观察继续引用原 ID。服务端高水位同时考虑当前结构、讲义、学生状态中的访问／成绩引用和反馈历史；新课时不能复用删除的身份。编辑器提交结构版本，服务端通过结构版本与既有班级关联条件原子保存，过期页面不能覆盖更新。

同题的既有成绩归属固定在 `problemNodeIds`，排序不会把原来计入某节点的成绩转给另一节点。访问归属另存 `problemAccessNodeIds`：原代码的评分取最后一个匹配课时，做题权限取第一个，不能把两种规则误合并。模板保存和班级模板复制携带这两个既有归属，课程 ID 仍是课时身份的范围。成绩表题目链接按服务端访问归属判断。纯测试验证得分、通过数、进度及访问归属；HTTP 测试验证重排前后被锁定学生仍被拒绝，开放原课时后才能进入，并保留讲义、访问设置和先修引用。原有模板复制及班级同步测试继续通过。

新观察由服务端生成课程、课时、题目名称快照；名称不参与客户端操作哈希，改名后原请求仍重放原回执。旧观察不回写或伪造快照；无法证明归属时显示“历史课时编号，名称未核实”。它们仍在全课程历史和待复测中，可靠课时筛选不会冒认这些旧记录。

`course-feedback-structure` 管理脚本要求域 ID，默认只读；显式 `execute: true` 才初始化高水位、结构版本与成绩归属，执行也检查结构未并发变化。测试覆盖只读零写入与显式初始化。本轮只在隔离课程执行，运行数据库未执行兼容脚本。

每条观察的状态独立计算。变更事件保存递增版本及转换后的状态；`feedback_version` 局部唯一索引约束“域 × 原观察 × 版本”。竞争操作只有一次有效转换，另一方收到 409 与当前状态。撤销处理必须引用当前有效处理事件，由该处理人或管理者执行；原观察、处理和纠错全部保留。

旧处理链按确定规则读取为版本 0，不插入合成初始化事件；原观察撤销优先，多条旧处理保留。首次新版转换写版本 1，并由同一唯一索引仲裁。重试在状态检查前重放原回执，但每次重新授权。

## 读取与页面一致性

名单最近有效观察在数据库按学生汇总，独立于历史第一页；撤销最新观察会回退到上一条有效观察。历史和待复测按绑定查询范围的游标分页。课程待办总数与当前筛选总数分别返回，已离开名单的历史学生保留待办和身份说明。

当前课程该题提交、录入时关联提交、处理时关联提交分别呈现。反馈接口不返回代码；提交摘要需要原有记录查看权限，代码页继续执行原权限校验。新增用例验证：无记录／代码阅读权限的授课教师可以记录、查询观察并跟进，摘要为空，代码页面拒绝访问。

A 与 B 共用页面内状态。草稿按域、活动、教师、课时、题目和学生隔离；换题、收起和 PJAX 重挂载保留原草稿。录入前固定请求编号与内容；未知回执只能重试原命令。成功只清理对应草稿。成功回执后的查询失败不会变成新的写入重试，未保存或待确认内容离开整页时提示。

异步读取绑定查询代次与已确认写入序号，避免旧回复覆盖新上下文。B 只为服务端授权的学生行提供入口，同时仅展开一个编辑区；教师自己的行、非名单行和公开导出无反馈操作。筛选与学生主行一起隐藏展开区。刷新后原行消失时显示明确提示，保留原对象，禁止新观察录入，不把草稿交给相邻学生。

课程成绩处理器补齐了原生 PJAX 片段响应。浏览器测试先改变真实成绩，再断言响应片段、旧节点断开、新分数出现及备注／课时保留；同时检查页面错误和控制台错误。早期仅断言请求 200 的检查不足，已替换，不计为最终通过证据。

管理页把讲义内容与学生可访问人数分别展示，分母为当前课程学生。批量确认列出动作、课时、名单与人数；后端返回逐学生结果，前端汇总整批后刷新一次，重试只针对失败项。节点访问使用单键更新，避免同时修改不同课时互相覆盖；恢复规则只清除访问覆盖，不删除提交、成绩或反馈。

## 复现入口与环境

本地 Windows Node 为 `22.20.0`，TypeScript `6.0.3`，测试 MongoDB `8.2.1`。运行环境记忆：WSL `Ubuntu-22.04` 的 Docker `hydro`，HTTP `8082`；容器 Node `22.16.0`，已安装 `hydrooj 5.0.7-dev.1` 与 `@hydrooj/ui-default 4.58.4-dev.41`，只读检查为 healthy。这些安装版本不包含本轮尚未部署的改动。

系统盘临时空间曾低于 MongoDB 的 500MiB 索引创建下限；该次失败不计为通过。最终回归把 TEMP/TMP 指向工作树 `.cache/feedback-runtime-temp` 后完整重跑通过。

在仓库已安装依赖的环境中，纯模块入口是 `yarn test:classroom-feedback`。完整测试可先在同一个终端设置以下隔离环境，再执行 `yarn test`（已有测试框架会创建临时数据库）：

```powershell
New-Item -ItemType Directory -Force .cache/feedback-runtime-temp | Out-Null
$env:TEMP = (Resolve-Path .cache/feedback-runtime-temp).Path
$env:TMP = $env:TEMP
$env:MONGOMS_SYSTEM_BINARY = (Resolve-Path .cache/mongodb-binaries/mongod-x64-win32-8.2.1.exe).Path
$env:NODE_OPTIONS = '--require=' + (Resolve-Path test/classroom-feedback-test-isolate.cjs).Path
corepack yarn test
```

MongoDB 二进制路径按实际缓存调整。隔离预加载器仅供测试使用，不用于启动正式 Hydro。浏览器验证在独立终端运行 `node test/classroom-feedback-browser.js`，取得其 `FEEDBACK_PREVIEW_URL` 后，以本机已有 Playwright 设置 `HYDRO_PLAYWRIGHT_MODULE`，执行 `node test/classroom-feedback-browser.spec.js <URL>`。测试启动独立课程、账户、默认模板和实际页面模块；仅绑定 loopback。当前应用浏览器控制通道不可用，最终证据来自独立无界面 Chrome，不操作用户现有浏览器标签。

容器检查先执行 `node test/prepare-classroom-feedback-container.cjs`，再将生成目录的**内容**复制到 `/tmp/hydro-feedback-validation-20261006/`，运行 `node --test /tmp/hydro-feedback-validation-20261006/test/*.spec.js`。复制的是纯测试模块，未替换 `/root/.hydro` 的安装包，不连接运行数据库。

浏览器联调使用真实默认模板、实际 Handler 和页面模块，原生 CSS 来自已确认设计所使用的 Hydro 源样式；页面脚本以独立测试入口打包。由于完整 webpack 门禁仍失败，这不等于完整发布包的端到端验收。
