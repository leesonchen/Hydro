# HydroOJ 课程界面与本地反馈静态原型

日期：2026-10-05。A 名单表格 + B 进度表原位记录已获用户同意。该目录保留确认时的静态设计；2026-10-06 正式接入结果见 [实施记录](../HYDRO-COURSE-FEEDBACK-IMPLEMENTATION-2026-10-06.md)。

打开 `index.html` 查看设计总览，或打开下列独立 HTML。`a-roster.html`、`b-scoreboard.html` 保留为旧预览地址的入口；`c-cards.html` 为上一轮未选方案，不参与本轮设计。

## 页面含义

| 页面 | 要回答的问题 | 页面内容 | 原型 |
| --- | --- | --- | --- |
| 课程内容 | 教什么、练什么？ | 现有章节、讲义和题目；进入对应课时的进度和反馈 | `course-content.html`、`course-lecture.html` |
| 课程进度 | 学生在系统里做到了哪一步？ | 沿用课程成绩规则与判题结果；学生 × 题目格内展开 B | `course-progress.html`、`course-progress-record.html` |
| 课程反馈 | 教师实际观察到了什么？ | A 名单、三个动作、最近记录、待复测 | `course-feedback.html`、`course-feedback-history.html` |
| 课程管理 | 课程如何运行？ | 原有认领、排名、临时调课学生、节点开放设置 | `course-manage.html`、`course-manage-extra.html`、`course-manage-nodes.html` |
| 待复测 | 哪些具体观察还要跟进？ | 反馈的待办子视图；原观察、最新提交、可选备注、完成跟进 | `pending-retests.html`、`retest-detail.html` |

课程进度采用真实成绩口径，不新增掌握度、教学评分或 RP。同题在多个课时复用时，共享“本课程该题”的提交和判题结果，不能计成每个课时独立完成一次。示例中的 100/0 为演示评测分数，正式界面沿用既有评分、罚分、排名和可见性规则，不能把所有 Wrong Answer 硬编码为 0。

## A + B 如何降低操作负担

- A：选一次课时和题目，然后沿学生名单点击一次动作。无提交学生同样能记录；备注、细项可空。搜索与筛选按需使用。
- B：点对应学生 × 题目的“记录”，再点一次动作。对象从当前格预填；其他格和分数保留。展开与收起在 HTML 中用片段链接演示。
- 两处使用同一 Hydro 本地事件服务，回执返回原位置。保存成功后展示学生、题目、动作与撤销入口，不要求确认弹框；未确认保存时保持原输入，使用原请求编号重试。
- 正式接入时，细项仅接受当前动作对应的合法值；切换动作不能误发另一个动作的细项。静态下拉框用分组展示可选内容。
- 不要求签到、点击开始授课、为全班逐一标记已掌握或逐课确认材料条件。

静态原型的下拉框、搜索、备注输入只展示字段布局；它们不筛选或保存。动作链接进入预设示例状态，页面顶部持续标明“示例数据，不保存”。题目链接展示讲义中的练习摘要，正式接入时打开既有题目页。提交摘要和课程编辑摘要同样保留既有功能入口，不另建 IDE 或完整编辑系统。

## 待复测的处理闭环

计数单位是观察条数；同一学生可以有多条待办。默认显示未撤销且未处理的“需复测”观察，完整展示学生、课时/题目、细项、原备注、记录教师/时间和最新提交。最新提交可能是录入后产生的参考信息，不能冒充原记录已经关联的提交。

教师已实际跟进后，可在清单直接点“完成跟进”，只需一次点击。需要了解详情时再进入上下文；跟进备注与提交编号均可空。处理后移出待办，但保留原始观察与处理人、时间、备注、可选关联提交。页面使用“已跟进”，不使用“复测通过”或“已掌握”。Accepted、其他核对记录和普通指导均不自动关闭待办。

静态流程可从两位学生中任意一位开始：

- `pending-retests.html` → 完成何雨桐 → `pending-retests-done.html` → 完成周亦辰 → `pending-retests-empty.html`。
- `pending-retests.html` → 完成周亦辰 → `pending-retests-zhou-done.html` → 完成何雨桐 → `pending-retests-empty.html`。
- `retest-done.html` / `retest-done-zhou.html` 展示已处理历史。之后仍需确认，回到预填学生的名单，新增一次“需复测”，不改写或重新打开旧事件。
- 误录时走撤销观察；它与完成实际跟进是不同动作。正式接入时仅原记录教师或有管理权限的用户可撤销，复测处理由当前授权教师执行。

正式接入时，待办数量必须是查询得到的完整未处理条数，不能把当前分页数量当总量。当前接口已有学生/题目筛选和分页，排序与精确计数需要补充核对；原型数字是固定示例。

## 课程管理与原有功能的关系

业务保持原有三个管理区；新增的是统一导航与原生样式，以及将日常反馈移至“课程反馈”。不会增加新的管理权限。

| 原有管理区 | 本轮保留的能力 | 注意事项 |
| --- | --- | --- |
| 班级成员管理 | 单个/批量代认领、取消认领，设置/恢复排名 | 管理现有班级成员的课程参与状态，不在这里新增/删除班级成员 |
| 临时调课学生 | 课程额外 UID 名单，认领与排名设置 | 仍通过既有课程编辑入口维护，不增加调课日历或自动到期 |
| 课程节点管理 | 讲义编辑、开放/关闭；题目开放/关闭/重置及批量操作 | 重置只移除手工题目开放设置，不清空提交、成绩或反馈 |

代码依据：基线 `01014e9957820d77bc4322438801ce6abdd8d0bc` 的 `packages/ui-default/pages/course_manage.page.tsx`，以及本分支 `packages/hydrooj/src/builtin/course-management/handler/course.ts` 的 `CourseManageHandler`、`getNodeAccessPatch` 和 `CourseScoreboardHandler`；既有课程编辑字段见 `packages/ui-default/templates/course_edit.html`。

核对发现原临时调课页的批量排名按钮虽然写“临时学生”，后端 `uid=0` 实际针对整个当前课程名单。原型明确写“全课程”，保留后端作用范围；正式实现须统一确认文字和对象范围。班级批量代认领/取消认领仍仅针对原班级名单。

课程编辑/节点管理继续按既有编辑权限授权。反馈教师权限不会自动扩大为课程编辑权限。学生按原有规则查看内容与课程成绩，不能看到教师反馈、待复测或管理操作。所有录入、查询、撤销、处理仍由 Hydro 自身会话、服务与数据库完成，不依赖 AI-EDU。

域内反馈功能开关关闭时，隐藏课程反馈、待复测及进度格里的记录动作；既有课程内容、成绩和管理继续按原规则工作。

## 样式与复现

`hydro-native.css` 从 Hydro 原生 common、typography、section、form、table、menu、navigation 样式编译。保留浅蓝 `#5f9fd6`、菜单选中粉色 `#ed5f82`、灰底 `#edf0f2`、原生白色区块与按钮、表格密度。原生导航图片为 `hydro-logo.png`。无外部字体、图库、脚本或网络依赖。

`proposals.css` 保留上一轮获认可的布局；`course-prototypes.css` 仅补充课程内容、事件列表、复测状态与管理表格。窄屏将侧栏下移，表格在自身区域横向滚动。名单按钮保持紧凑，跟进按钮保持可见。

可在此目录运行 `node build-course-prototypes.cjs` 重新生成 HTML 与 `prototype-files.json`。不要重新运行旧 `.cache/build-feedback-proposals.cjs`，它会覆盖已确认的 A/B 入口与本轮总览。截图是浏览器实际渲染结果，单独保存。

本轮只改本目录中的静态设计文件；先前未确认的正式 UI 改动留在工作树中，不继续接入、不提交发布、不替换或重启 WSL Docker `hydro` 中运行的包。PR #11 仍保持 Draft。
